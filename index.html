ติดตั้ง

Hands-on

// LED บนบอร์ดต่อขั้วบวกไว้ที่ 3V3 จึงติดเมื่อเขียน LOW
void setup() {
  pinMode(LED_RED, OUTPUT);
  digitalWrite(LED_RED, HIGH);   // ดับ

ทำไมต้องใช้ core non-mbed ในคอร์สนี้?

เช็กความเข้าใจ

ถ้า __cplusplus ได้ 201103 จะใช้ if constexpr ได้ไหม?

ไม่ได้ if constexpr เป็นของ C++17 ต้องเพิ่ม flag -std=gnu++17 หรือเลี่ยงไปใช้ template overload

"Global variables use" นับ stack ด้วยไหม?

ไม่นับ นับเฉพาะ .data + .bss ที่รู้ขนาดตอน link ตัวแปร local บน stack ไม่อยู่ในตัวเลขนี้

มุมสัมภาษณ์

ถูกถามบ่อยว่า "อธิบายขั้นตอน build firmware" ให้ตอบเป็นลำดับ preprocess → compile → link (linker script กำหนด address) → objcopy → flash และบอกว่า .elf มี debug symbol ส่วน .hex/.bin คือ image ที่ลงชิป

02

โมดูล A · C++ สำหรับคนเขียน C

Reference, const และ constexpr แทน #define

25 นาที · ฮาร์ดแวร์: บอร์ดอย่างเดียว

เป้าหมาย เลิกใช้ #define กับค่าคงที่ และส่งพารามิเตอร์ด้วย reference ได้ถูกที่

C

ค่าคงที่ใช้ #define ไม่มี type ไม่มี scope แก้ตัวแปรของผู้เรียกต้องส่ง pointer

C++

constexpr มี type และคำนวณตอน compile ไม่กิน RAM ส่วน T& คือชื่อเล่นของตัวแปรเดิม ไม่มี null ไม่ต้องเขียน *

Hands-on

rgb_cycle.ino
constexpr uint8_t kLedPins[] = {LED_RED, LED_GREEN, LED_BLUE};
constexpr size_t  kLedCount  = sizeof(kLedPins) / sizeof(kLedPins[0]);
constexpr uint32_t kStepMs   = 150;

void allOff() {
  for (uint8_t pin : kLedPins) {   // range-based for (C++11)
    digitalWrite(pin, HIGH);
  }
}

void nextIndex(size_t& idx) {      // reference: แก้ตัวแปรของผู้เรียกได้เลย
  idx = (idx + 1) % kLedCount;
}

size_t current = 0;

void setup() {
  for (uint8_t pin : kLedPins) pinMode(pin, OUTPUT);
  allOff();
}

void loop() {
  allOff();
  digitalWrite(kLedPins[current], LOW);
  delay(kStepMs);
  nextIndex(current);
}

ลองเพิ่มฟังก์ชัน void printPin(const uint8_t& p) แล้วพยายามเขียน p = 0; ข้างใน ดู error ที่ compiler ฟ้อง นี่คือประโยชน์ของ const: จับบั๊กตอน compile

เช็กความเข้าใจ

เมื่อไหร่ควรส่ง const T& แทนส่งค่า?

เมื่อ T ใหญ่กว่า register (struct, buffer) เพื่อเลี่ยงการ copy ส่วน int, float, pointer ส่งค่าตรง ๆ เร็วกว่าและอ่านง่ายกว่า

constexpr ต่างจาก const อย่างไร?

const = ห้ามแก้ แต่อาจรู้ค่าตอน runtime ส่วน constexpr = ต้องรู้ค่าตอน compile จึงใช้เป็นขนาด array หรือ template argument ได้

มุมสัมภาษณ์

"ทำไมไม่ใช้ #define?" ตอบ: ไม่มี type checking, ไม่เคารพ namespace/scope, debugger มองไม่เห็นชื่อ และอาจเกิด side effect จาก macro expansion

โมดูล A · C++ สำหรับคนเขียน C

20 นาที · ฮาร์ดแวร์: บอร์ดอย่างเดียว

เป้าหมาย จัดระเบียบชื่อและเข้าใจว่าทำไม C++ ต้องมี name mangling

C

ชื่อฟังก์ชันซ้ำไม่ได้ ต้องตั้ง log_int, log_float และ enum ปนกับ int ได้ทุกที่

C++

overload ชื่อเดียวหลายพารามิเตอร์ได้ namespace กันชื่อชน enum class ไม่แปลงเป็น int เอง กำหนดขนาด : uint8_t ได้

Hands-on

เช็กความเข้าใจ

ถ้า library เขียนด้วย C ต้อง include อย่างไร?

ครอบ header ด้วย extern "C" { … } เพื่อให้ linker หา symbol ชื่อแบบ C เจอ ถ้าไม่ครอบจะ error undefined reference

ทำไม enum class ปลอดภัยกว่า enum?

ไม่แปลงเป็น int เอง ชื่อ enumerator ไม่หลุดออกมาใน scope ภายนอก และกำหนด underlying type ได้ จึงคุมขนาดในหน่วยความจำได้

class: encapsulation และ constructor

30 นาที · ฮาร์ดแวร์: LED + R 1 kΩ

เป้าหมาย เขียน class Led ที่ซ่อนเรื่อง active-LOW ไว้ข้างใน

C

struct เก็บข้อมูล + ฟังก์ชัน led_on(&led) แยกกัน ใครก็แก้ field ได้

C++

ข้อมูล (private) และพฤติกรรม (public) อยู่ด้วยกัน คอมไพล์แล้วได้โค้ดขนาดใกล้เคียงกัน เพราะ this ก็คือ pointer ที่ส่งเข้าไปแบบซ่อน

Hands-on

led_class.ino
class Led {
public:
  Led(uint8_t pin, bool activeLow) : pin_(pin), activeLow_(activeLow) {}

  void begin() { pinMode(pin_, OUTPUT); off(); }
  void on()     { write(true); }
  void off()    { write(false); }
  void toggle() { write(!isOn_); }
  bool isOn() const { return isOn_; }   // const method: ไม่แก้ state

private:
  void write(bool on) {
    isOn_ = on;
    digitalWrite(pin_, (on != activeLow_) ? HIGH : LOW);
  }
  uint8_t pin_;
  bool activeLow_;
  bool isOn_ = false;
};

Led red(LED_RED, true);   // บนบอร์ด: active-LOW
Led ext(D2, false);       // ภายนอก: active-HIGH

void setup() {
  red.begin();
  ext.begin();
}

void loop() {
  red.toggle();
  ext.toggle();
  delay(300);
}

ทำไมมี begin() แยก ไม่เรียก pinMode ใน constructor? เพราะ object global ถูกสร้างก่อน main() และก่อน init() ฮาร์ดแวร์อาจยังไม่พร้อม เป็น pattern มาตรฐานของ embedded C++

ทดลอง: ย้ายโค้ดไปไว้ที่ src/Led.h (สร้างโฟลเดอร์ src ในโฟลเดอร์ sketch, บรรทัดแรกใส่ #pragma once และ #include <Arduino.h>) แล้ว #include "src/Led.h" จะใช้ต่อในบท 11

เช็กความเข้าใจ

member initializer list (: pin_(pin)) ดีกว่ากำหนดค่าใน body อย่างไร?

สร้าง member ด้วยค่าที่ถูกต้องตั้งแต่แรก ไม่ต้อง default-construct แล้วค่อย assign และจำเป็นสำหรับ member ที่เป็น const หรือ reference

object Led ใช้ RAM กี่ byte โดยประมาณ?

ราว 3–4 byte (pin_, activeLow_, isOn_ + padding) ฟังก์ชันไม่กิน RAM ต่อ object เพราะอยู่ใน flash ใช้ร่วมกัน

มุมสัมภาษณ์

"Static initialization order fiasco" คือคำถามระดับกลาง: ลำดับการสร้าง global object ข้ามไฟล์ไม่ถูกกำหนด ทางแก้คือ begin() หรือ function-local static

RAII และ destructor

25 นาที · ฮาร์ดแวร์: Pot 10 kΩ ที่ A0

เป้าหมาย ใช้ scope ควบคุม resource อัตโนมัติ: จับเวลา, ปิด/เปิด interrupt

RAII (Resource Acquisition Is Initialization): ขอ resource ใน constructor คืนใน destructor แล้ว compiler จะเรียก destructor ให้เมื่อออกจาก scope เสมอ จึงไม่มีทางลืม unlock หรือ enable_irq แม้จะ return กลางทาง C ไม่มีกลไกนี้

Hands-on

raii.ino
class ScopedTimer {
public:
  explicit ScopedTimer(const char* label) : label_(label), start_(micros()) {}
  ~ScopedTimer() {
    uint32_t us = micros() - start_;
    Serial.print(label_); Serial.print(": "); Serial.print(us); Serial.println(" us");
  }
  ScopedTimer(const ScopedTimer&) = delete;             // ห้าม copy
  ScopedTimer& operator=(const ScopedTimer&) = delete;
private:
  const char* label_;
  uint32_t start_;
};

// ปิด interrupt แบบซ้อนได้: เก็บสถานะเดิมแล้วคืนค่าเดิม
class CriticalSection {
public:
  CriticalSection() : primask_(__get_PRIMASK()) { __disable_irq(); }
  ~CriticalSection() { __set_PRIMASK(primask_); }
private:
  uint32_t primask_;
};

void setup() { Serial.begin(115200); }

void loop() {
  long sum = 0;
  {
    ScopedTimer t("analogRead x100");
    for (int i = 0; i < 100; ++i) sum += analogRead(A0);
  }                                   // destructor ทำงานตรงนี้
  Serial.print("avg = "); Serial.println(sum / 100);
  delay(1000);
}

เช็กความเข้าใจ

ทำไมต้อง = delete copy constructor?

ถ้า copy ได้ จะมี 2 object ที่ destructor ทำงานซ้ำ เช่น เปิด interrupt 2 ครั้ง หรือพิมพ์เวลาซ้ำ resource ที่มีเจ้าของคนเดียวควรห้าม copy

CriticalSection ใช้กับ BLE (SoftDevice) ได้ไหม?

ใช้ได้แค่ช่วงสั้นมาก ไม่กี่ไมโครวินาที ถ้าปิดนาน SoftDevice จะพลาด timing ของวิทยุ ในงานจริงใช้ sd_nvic_critical_region_enter แทน

มุมสัมภาษณ์

ถ้าถูกถาม "ข้อดีที่สุดของ C++ เหนือ C ใน embedded" RAII คือคำตอบที่ดี เพราะไม่มี runtime overhead และกำจัดบั๊ก resource leak ทั้งกลุ่ม

30 นาที · ฮาร์ดแวร์: ปุ่มกดที่ D1

เป้าหมาย เขียน debounce แบบ non-blocking เป็น class ที่ไม่พึ่ง Arduino (จะ test ได้ในบท 15)

ต่อปุ่มระหว่าง D1 กับ GND แล้วใช้ INPUT_PULLUP ปล่อย = HIGH, กด = LOW หน้าสัมผัสจะเด้งหลายครั้งในไม่กี่มิลลิวินาที ถ้าไม่ debounce กดครั้งเดียวจะนับได้หลายครั้ง

Hands-on

สร้างไฟล์ src/Debouncer.h ในโฟลเดอร์ sketch

src/Debouncer.h
#pragma once
#include <stdint.h>

// Pure logic: ไม่เรียก Arduino API เลย จึง test บน PC ได้
class Debouncer {
public:
  enum class Event : uint8_t { None, Pressed, Released };

  explicit Debouncer(uint32_t stableMs = 20) : stableMs_(stableMs) {}

  // raw: true = กดอยู่ (แปลง active-LOW มาแล้ว), nowMs: เวลาปัจจุบัน
  Event update(bool raw, uint32_t nowMs) {
    if (raw != lastRaw_) {  // ยังเด้งอยู่ → เริ่มจับเวลาใหม่
      lastRaw_ = raw;
      changedAt_ = nowMs;
      return Event::None;
    }
    if (raw != stable_ && (nowMs - changedAt_) >= stableMs_) {
      stable_ = raw;
      return stable_ ? Event::Pressed : Event::Released;
    }
    return Event::None;
  }

  bool isPressed() const { return stable_; }

private:
  uint32_t stableMs_;
  uint32_t changedAt_ = 0;
  bool lastRaw_ = false;
  bool stable_ = false;
};

constexpr uint8_t kButtonPin = D1;
enum class Mode : uint8_t { Off, Slow, Fast };

Debouncer button;
Mode mode = Mode::Off;
uint32_t lastToggle = 0;
bool ledOn = false;

Mode next(Mode m) {
  switch (m) {
    case Mode::Off:  return Mode::Slow;
    case Mode::Slow: return Mode::Fast;
    case Mode::Fast: return Mode::Off;
  }
  return Mode::Off;
}

uint32_t periodMs(Mode m) { return m == Mode::Slow ? 500 : 100; }

void setup() {
  pinMode(kButtonPin, INPUT_PULLUP);
  pinMode(LED_GREEN, OUTPUT);
  digitalWrite(LED_GREEN, HIGH);
}

void loop() {
  uint32_t now = millis();
  bool pressed = (digitalRead(kButtonPin) == LOW);
  if (button.update(pressed, now) == Debouncer::Event::Pressed) {
    mode = next(mode);
  }
  if (mode == Mode::Off) {
    digitalWrite(LED_GREEN, HIGH);
  } else if (now - lastToggle >= periodMs(mode)) {
    lastToggle = now;
    ledOn = !ledOn;
    digitalWrite(LED_GREEN, ledOn ? LOW : HIGH);
  }
}

ทำไม now - lastToggle ยังถูกต้องแม้ millis() overflow (ราว 49.7 วัน)?

การลบ unsigned 32-bit เป็น modulo 2³² ผลต่างจึงถูกเสมอตราบใดที่ช่วงเวลาไม่เกิน 49.7 วัน ห้ามเขียนแบบ now > lastToggle + period เพราะพังตอน overflow

ทำไม switch มี return Mode::Off ท้ายฟังก์ชันอีก?

บาง compiler เตือนว่า control reaches end of non-void function แม้จะครอบทุก case แล้ว ใส่ไว้เพื่อความปลอดภัยและ warning-free

Template: RingBuffer<T, N>

30 นาที · ฮาร์ดแวร์: Pot ที่ A0

เป้าหมาย เขียน container ขนาดคงที่ใช้ซ้ำได้ทุกชนิด โดยไม่ใช้ heap

C

ทำ buffer สำหรับ int, float แยกกัน หรือใช้ void* + macro ซึ่งไม่มี type safety

C++

template ให้ compiler สร้างโค้ดเฉพาะชนิดให้ ขนาด N เป็นค่าตอน compile ตรวจได้ด้วย static_assert

Hands-on

สร้าง src/RingBuffer.h

src/RingBuffer.h
#pragma once
#include <stddef.h>

// FIFO ขนาดคงที่ ไม่ใช้ heap — ขนาด N ถูกกำหนดตอน compile
template <typename T, size_t N>
class RingBuffer {
  static_assert(N > 0, "N must be > 0");

public:
  bool push(const T& v) {
    if (count_ == N) return false;  // เต็ม
    buf_[head_] = v;
    head_ = (head_ + 1) % N;
    ++count_;
    return true;
  }

  bool pop(T& out) {
    if (count_ == 0) return false;  // ว่าง
    out = buf_[tail_];
    tail_ = (tail_ + 1) % N;
    --count_;
    return true;
  }

  // เต็มแล้วให้ทิ้งตัวเก่าสุด (เหมาะกับ moving average)
  void pushOverwrite(const T& v) {
    if (count_ == N) {
      T dropped;
      pop(dropped);
    }
    push(v);
  }

  size_t size() const { return count_; }
  bool full() const { return count_ == N; }
  const T& at(size_t i) const { return buf_[(tail_ + i) % N]; }  // 0 = เก่าสุด

private:
  T buf_[N]{};
  size_t head_ = 0, tail_ = 0, count_ = 0;
};

template <typename T, size_t N>
float average(const RingBuffer<T, N>& rb) {
  if (rb.size() == 0) return 0.0f;
  float sum = 0;
  for (size_t i = 0; i < rb.size(); ++i) sum += rb.at(i);
  return sum / rb.size();
}

ยังไม่ปลอดภัย เพราะ count_ ถูกแก้จากทั้งสองฝั่ง ต้องครอบด้วย CriticalSection หรือออกแบบ SPSC ที่ฝั่ง producer แก้แค่ head ฝั่ง consumer แก้แค่ tail

  • ใช้ std::array / buffer ขนาดคงที่ หลีกเลี่ยง std::vector, std::function ที่อาจจอง heap เอง
  • embedded มักปิด exceptions และ RTTI (-fno-exceptions -fno-rtti) จึงจัดการ error ด้วยค่าที่ return

ตัวแปร static ภายในฟังก์ชันอยู่ส่วนไหน?

เตรียมอธิบาย .text / .data / .bss / heap / stack ด้วยรูปนี้ได้ภายใน 1 นาที เป็นคำถามที่เจอเกือบทุกที่

เป้าหมาย เขียน ISR ที่ถูกต้อง และแชร์ข้อมูลระหว่าง ISR กับ loop อย่างปลอดภัย

Hands-on

isr_count.ino
constexpr uint8_t kButtonPin = D1;
volatile uint32_t pressCount = 0;   // volatile: ค่าเปลี่ยนนอก flow ปกติ ห้าม cache

void setup() {
  Serial.begin(115200);
  pinMode(kButtonPin, INPUT_PULLUP);
  // lambda ที่ไม่ capture อะไร แปลงเป็น function pointer ได้
  attachInterrupt(digitalPinToInterrupt(kButtonPin), [] {
    pressCount = pressCount + 1;
  }, FALLING);
}

void loop() {
  uint32_t count;
  noInterrupts();          // copy ออกมาแบบ atomic
  count = pressCount;
  interrupts();
  Serial.println(count);
  delay(500);
}

กดปุ่ม 1 ครั้ง ตัวเลขมักเพิ่มมากกว่า 1 นั่นคือ bounce ที่เห็นในบท 6 ข้อสรุป: ISR บนปุ่มกลไกต้อง debounce ด้วยเวลา (เช่นเช็ก millis() ใน ISR หรือส่ง event ให้ loop จัดการ)

เช็กความเข้าใจ

volatile ทำให้ pressCount++ เป็น atomic ไหม?

ไม่ volatile แค่บังคับให้อ่าน/เขียน memory จริงทุกครั้ง แต่ ++ คือ load-add-store 3 คำสั่ง ถูกแทรกกลางได้ ต้องใช้ critical section หรือ std::atomic

อะไรห้ามทำใน ISR?

delay(), Serial.print(), malloc/new, ทำงานนาน และเรียกฟังก์ชันที่ไม่ reentrant ให้ ISR ตั้ง flag หรือ push ลง buffer แล้วกลับเร็วที่สุด

มุมสัมภาษณ์

volatile คือคำถามที่ถูกถามบ่อยที่สุดในสาย embedded ตอบให้ครบ 3 กรณี: ตัวแปรที่ ISR แก้, memory-mapped register, ตัวแปรที่แชร์ระหว่าง thread (และบอกว่ามันไม่ใช่ synchronization)

Mini project: cooperative scheduler

เป้าหมาย รวมทุกอย่างเป็น firmware ที่ไม่มี delay() เลย โครงสร้างแบบนี้ใช้จริงก่อนจะขึ้น RTOS

Hands-on

ตั้งชื่อโฟลเดอร์ firmware/ และไฟล์ firmware.ino (Arduino บังคับให้ชื่อตรงกัน) ใน src/ มี Led.h, Debouncer.h, RingBuffer.h จากบทก่อน

firmware/firmware.ino
#include "src/Led.h"
#include "src/Debouncer.h"
#include "src/RingBuffer.h"

#if __has_include("src/version.h")
#include "src/version.h"          // CI สร้างไฟล์นี้ (บท 17)
#else
#define FW_VERSION "dev"
#endif

constexpr uint8_t kButtonPin = D1;
constexpr uint8_t kPotPin    = A0;

Led status(LED_GREEN, true);
Led ext(D2, false);
Debouncer button;
RingBuffer<uint16_t, 16> samples;
bool paused = false;

struct Task {
  uint32_t periodMs;
  uint32_t lastRunMs;
  void (*run)();
};

void blinkTask() { if (!paused) status.toggle(); }

void buttonTask() {
  bool pressed = digitalRead(kButtonPin) == LOW;
  if (button.update(pressed, millis()) == Debouncer::Event::Pressed) {
    paused = !paused;
    ext.toggle();
  }
}

void sensorTask() { samples.pushOverwrite(analogRead(kPotPin)); }

void reportTask() {
  Serial.print("avg:");     Serial.print(average(samples));
  Serial.print(" paused:"); Serial.println(paused ? 1 : 0);
}

Task tasks[] = {
  {500, 0, blinkTask},
  {5,   0, buttonTask},
  {20,  0, sensorTask},
  {200, 0, reportTask},
};

// พิมพ์ตัวเลข 50–5000 แล้ว Enter เพื่อเปลี่ยนรอบกระพริบ
void handleSerial() {
  static char buf[16];
  static size_t len = 0;
  while (Serial.available()) {
    char c = Serial.read();
    if (c == '\n' || c == '\r') {
      if (len > 0) {
        buf[len] = '\0';
        long ms = atol(buf);
        if (ms >= 50 && ms <= 5000) tasks[0].periodMs = ms;
        len = 0;
      }
    } else if (len < sizeof(buf) - 1) {
      buf[len++] = c;
    }
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(kButtonPin, INPUT_PULLUP);
  status.begin();
  ext.begin();
  Serial.print("fw "); Serial.println(FW_VERSION);
}

void loop() {
  uint32_t now = millis();
  for (Task& t : tasks) {
    if (now - t.lastRunMs >= t.periodMs) {
      t.lastRunMs = now;
      t.run();
    }
  }
  handleSerial();
}

ถ้า reportTask ใช้เวลา 30 ms จะเกิดอะไรกับ buttonTask?

buttonTask ถูกเลื่อนไปจน reportTask จบ เพราะเป็น cooperative (ไม่มี preemption) ทุก task ต้องสั้น ถ้าทำไม่ได้คือสัญญาณว่าถึงเวลาใช้ RTOS

ทำไม Task ใช้ function pointer ไม่ใช้ std::function?

ทำไมทีมไม่ commit ตรงเข้า main?

main ควร build ได้และ test ผ่านเสมอ การผ่าน branch + PR ให้ CI และคนอื่นตรวจก่อน และย้อนกลับง่าย

เป้าหมาย รัน test ของ Debouncer และ RingBuffer บน PC ได้ในไม่กี่วินาที โดยไม่ต้องเสียบบอร์ด

Debouncer รับเวลาเป็นพารามิเตอร์ (nowMs) แทนการเรียก millis() เอง นี่คือเทคนิค dependency injection แบบง่ายที่สุด ทำให้ test ควบคุมเวลาได้ทุกมิลลิวินาที

Hands-on

test/test_main.cpp
#include <cstdio>
#include <cstdlib>
#include "RingBuffer.h"
#include "Debouncer.h"

static int failures = 0;
#define CHECK(cond)                                                    \
  do {                                                                 \
    if (!(cond)) {                                                     \
      std::printf("FAIL %s:%d  %s\n", __FILE__, __LINE__, #cond);      \
      ++failures;                                                      \
    }                                                                  \
  } while (0)

static void test_ringbuffer() {
  RingBuffer<int, 3> rb;
  CHECK(rb.size() == 0);
  CHECK(rb.push(1) && rb.push(2) && rb.push(3));
  CHECK(!rb.push(4));          // เต็มแล้ว
  int v = 0;
  CHECK(rb.pop(v) && v == 1);  // FIFO: ออกตัวแรกก่อน
  rb.pushOverwrite(4);
  rb.pushOverwrite(5);         // เต็ม → ทิ้ง 2
  CHECK(rb.at(0) == 3 && rb.at(2) == 5);
  CHECK(average(rb) == 4.0f);
}

static void test_debouncer() {
  using E = Debouncer::Event;
  Debouncer d(20);
  CHECK(d.update(true, 0) == E::None);   // เริ่มกด
  CHECK(d.update(false, 5) == E::None);  // เด้ง
  CHECK(d.update(true, 8) == E::None);   // เด้ง
  CHECK(d.update(true, 20) == E::None);  // นิ่งมาแค่ 12 ms
  CHECK(d.update(true, 28) == E::Pressed);
  CHECK(d.isPressed());
  CHECK(d.update(true, 40) == E::None);  // กดค้าง ไม่ยิงซ้ำ
}

int main() {
  test_ringbuffer();
  test_debouncer();
  if (failures == 0) std::puts("ALL TESTS PASSED");
  return failures == 0 ? EXIT_SUCCESS : EXIT_FAILURE;
}
terminal

g++ -std=c++17 -Wall -Wextra -Werror -Ifirmware/src test/test_main.cpp -o test_runner
./test_runner
# ALL TESTS PASSED

ทดลองทำให้ test แดง: แก้ >= stableMs_ ใน Debouncer.h เป็น > แล้วรันใหม่ ดูว่าบรรทัดไหน FAIL จากนั้นแก้กลับ แล้ว commit ด้วย test: add host unit tests

ในงานจริงใช้ framework เช่น GoogleTest, Catch2 หรือ Unity (สำหรับ C) แต่หลักการเหมือนกัน: CHECK เงื่อนไข, รายงานบรรทัดที่พัง, exit code ≠ 0 เมื่อ fail เพื่อให้ CI รู้

เช็กความเข้าใจ

ทำไม exit code สำคัญ?

CI ตัดสินผ่าน/ไม่ผ่านจาก exit code ของคำสั่ง 0 = ผ่าน อย่างอื่น = fail และหยุด pipeline

จะ test โค้ดที่เรียก digitalRead() ได้อย่างไร?

ซ่อนการเข้าถึงฮาร์ดแวร์ไว้หลัง interface (เช่น ISensor บท 7) แล้วใส่ fake/mock ตอน test หรือส่งค่าที่อ่านได้เข้าฟังก์ชันแทนให้ฟังก์ชันไปอ่านเอง

มุมสัมภาษณ์

"คุณ test firmware อย่างไร" ตอบเป็นชั้น: unit test บน host สำหรับ logic, HIL test บนบอร์ดจริงสำหรับ driver, system test สำหรับฟีเจอร์ แล้วบอกว่าชั้นแรกรันใน CI ทุก commit

Hands-on

.github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:

env:
  BOARD_URL: https://files.seeedstudio.com/arduino/package_seeeduino_boards_index.json
  FQBN: Seeeduino:nrf52:xiaonRF52840Sense   # ใช้ค่าที่ได้จาก board listall

jobs:
  host-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build tests
        run: g++ -std=c++17 -Wall -Wextra -Werror -Ifirmware/src test/test_main.cpp -o test_runner
      - name: Run tests
        run: ./test_runner
      - name: Static analysis
        run: |
          sudo apt-get update && sudo apt-get install -y cppcheck
          cppcheck --error-exitcode=1 --enable=warning,performance --std=c++17 -Ifirmware/src test/test_main.cpp

  build-firmware:
    needs: host-tests
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      - run: pip install adafruit-nrfutil   # core ใช้ตอนแพ็ก .zip บน Linux
      - uses: arduino/setup-arduino-cli@v2
      - name: Install board core
        run: |
          arduino-cli core update-index --additional-urls "$BOARD_URL"
          arduino-cli core install Seeeduino:nrf52 --additional-urls "$BOARD_URL"
      - name: Compile
        run: arduino-cli compile --fqbn "$FQBN" --additional-urls "$BOARD_URL" --output-dir out firmware
      - uses: actions/upload-artifact@v4
        with:
          name: firmware
          path: out/

คำถามที่ควรตอบได้ภายใน 1 นาที

C++ ต่างจาก C ในงาน embedded อย่างไร มีต้นทุนอะไรบ้าง?

ได้ class, RAII, reference, template, constexpr, enum class, namespace ที่ส่วนใหญ่ไม่มี runtime cost ส่วนที่มีต้นทุนคือ virtual (vtable), exceptions, RTTI, heap ผ่าน STL บางตัว จึงเลือกใช้เป็น subset

volatile ใช้เมื่อไหร่ และไม่ได้ช่วยอะไร?

ตัวแปรที่ ISR แก้, register ของ peripheral, ข้อมูลที่แชร์ระหว่าง context ไม่ได้ทำให้ atomic และไม่ใช่ memory barrier

ISR ที่ดีเป็นอย่างไร?

สั้น, ไม่ block, ไม่จอง memory, ตั้ง flag หรือ push ลง ring buffer แล้วให้ main/task ประมวลผล ข้อมูลที่แชร์ต้องป้องกันด้วย critical section

ทำไมเลี่ยง dynamic allocation หลัง init?

fragmentation, เวลาไม่แน่นอน, และ fail ได้ตอนรันไปนาน ๆ ระบบที่ต้องทำงานต่อเนื่องจึงจองทุกอย่างแบบ static

อธิบาย RAII พร้อมตัวอย่าง

ผูกอายุ resource กับ object: CriticalSection ปิด interrupt ใน ctor คืนค่าใน dtor ออกจาก scope ทางไหนก็คืนเสมอ

debounce มีกี่วิธี?

ฮาร์ดแวร์ (RC + Schmitt trigger) และซอฟต์แวร์ (รอให้นิ่งตามเวลา หรือ sample หลายครั้ง) เลือกตามต้นทุน BOM กับ CPU

merge กับ rebase เลือกอย่างไร?

merge เก็บประวัติจริงและปลอดภัยกับ branch ที่แชร์ rebase ทำประวัติเส้นตรง ใช้กับ branch ส่วนตัวก่อนเปิด PR

pipeline CI/CD ของ firmware ควรมีอะไร?

build ทุก target, unit test บน host, static analysis, เก็บ artifact, release ตาม tag พร้อมเวอร์ชันฝังใน binary, ขั้นต่อไปคือ HIL test บน runner ที่ต่อบอร์ดจริง

ประสบการณ์ PCB, failure analysis และ V&V ที่มีอยู่คือจุดแข็งที่คนสาย firmware ล้วนไม่มี ใน portfolio ให้เชื่อม 2 ฝั่ง เช่น อธิบายว่าเลือกค่า R ของ LED และ debounce time จากอะไร
