Goal Split work into branches, and resolve merge conflicts without panic

Hands-on: create a conflict, then resolve it

terminal
git switch -c feature/fast-blink
# in firmware.ino change {500, 0, blinkTask} to {250, 0, blinkTask}
git commit -am "feat: faster default blink"

git switch main
# change the same line to {1000, 0, blinkTask}
git commit -am "chore: slower default blink"

git merge feature/fast-blink      # → CONFLICT
firmware.ino during the conflict
<<<<<<< HEAD
  {1000, 0, blinkTask},
=======
  {250, 0, blinkTask},
>>>>>>> feature/fast-blink
terminal
# keep the line you want and delete the <<< === >>> markers
git add firmware/firmware.ino
git commit                         # completes the merge
git log --oneline --graph --all
git branch -d feature/fast-blink

merge keeps the real history (with a merge commit), while git rebase main replays the branch's commits on top of main for a straight-line history. Rule: never rebase a branch someone else has already pulled.

Check your understanding

You resolved a conflict wrongly and want to start over. What do you do?

git merge --abort before you commit takes you back to the state before the merge.

Why do teams not commit straight to main?

main should always build and pass its tests. Going through a branch + PR lets CI and teammates check first, and makes changes easy to revert.
