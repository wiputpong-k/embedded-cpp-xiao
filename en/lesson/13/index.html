Mini project 1: cooperative scheduler

30 min · Hardware: LED + button + pot

In this lesson
  1. Prepare the circuit and the project
  2. Test it
  3. Check your understanding

Goal Combine the LED, button and pot into one firmware with no delay() at all. Real products use this structure before moving to an RTOS

Real firmware has to do several things at once: blink an LED, read a button, sample a sensor. With delay(), one job blocks all the others. The simplest fix is a cooperative scheduler: split the work into short tasks, give each task its own period, and let loop() check which tasks are due.

Prepare the circuit and the project

  1. Wire all three parts on the same breadboard: LED + resistor on D2 (lesson 04), pot on A0 (lesson 06) and the button on D1 (lesson 07).
  2. Create a new sketch and use File → Save As… to name it firmware. You get a firmware/ folder containing firmware.ino (Arduino requires the folder and the .ino file to share a name).
  3. Create a src folder inside firmware/ and copy in three files from earlier lessons: Led.h (lesson 05), Debouncer.h (lesson 07) and RingBuffer.h (lesson 10).
  4. Paste the code below into firmware.ino and click Upload.
firmware/firmware.ino
#include <Adafruit_TinyUSB.h>   // enables USB and Serial (required by this core)
#include "src/Led.h"
#include "src/Debouncer.h"
#include "src/RingBuffer.h"

#if __has_include("src/version.h")
#include "src/version.h"          // generated by CI (lesson 23)
#else
#define FW_VERSION "dev"
#endif

constexpr uint8_t kButtonPin = D1;
constexpr uint8_t kPotPin    = A0;

Led status(LED_GREEN, true);
Led ext(D2, false);
Debouncer button;
xiao::RingBuffer<uint16_t, 16> samples;
bool paused = false;

struct Task {
  uint32_t periodMs;
  uint32_t lastRunMs;
  void (*run)();
};

void blinkTask() { if (!paused) status.toggle(); }

void buttonTask() {
  bool pressed = digitalRead(kButtonPin) == LOW;
  if (button.update(pressed, millis()) == Debouncer::Event::Pressed) {
    paused = !paused;
    ext.toggle();
  }
}

void sensorTask() { samples.pushOverwrite(analogRead(kPotPin)); }

void reportTask() {
  Serial.print("avg:");     Serial.print(average(samples));
  Serial.print(" paused:"); Serial.println(paused ? 1 : 0);
}

Task tasks[] = {
  {500, 0, blinkTask},
  {5,   0, buttonTask},
  {20,  0, sensorTask},
  {200, 0, reportTask},
};

void setup() {
  Serial.begin(115200);
  pinMode(kButtonPin, INPUT_PULLUP);
  status.begin();
  ext.begin();
  Serial.print("fw "); Serial.println(FW_VERSION);
}

void loop() {
  uint32_t now = millis();
  for (Task& t : tasks) {
    if (now - t.lastRunMs >= t.periodMs) {
      t.lastRunMs = now;
      t.run();
    }
  }
}

Test it

  1. The green on-board LED should blink every 0.5 s.
  2. Press the button: the green LED stops blinking and the external LED turns on. Press again to go back.
  3. Open Tools → Serial Plotter (115200 baud) and turn the pot. The avg line should follow.

Everything runs at once without a single delay(). Try changing the numbers in tasks[], e.g. set blinkTask to 100, and upload again.

Check your understanding

If reportTask takes 30 ms, what happens to buttonTask?

buttonTask waits until reportTask finishes, because scheduling is cooperative (no preemption). Every task must be short; when that is no longer possible, it is time for an RTOS.

Why does Task use a function pointer instead of std::function?

A function pointer is 4 bytes, never allocates and is predictable. std::function may allocate on the heap when it captures data.
