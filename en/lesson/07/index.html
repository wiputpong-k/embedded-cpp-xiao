Buttons and debounce

30 min · Hardware: Button on D1

In this lesson
  1. Wire it up
  2. Why debounce
  3. Hands-on
  4. How the Debouncer works
  5. Check your understanding

Goal Wire a button, and write non-blocking debounce as a class that does not depend on Arduino (you will test it on a PC in lesson 19)

Wire it up

A tactile button has 4 legs. The legs on the same side are pairs that are already connected inside. If you place it the wrong way round, the button looks permanently pressed. The safe trick is to use two legs that are diagonally opposite, because they always belong to different pairs.

  1. Unplug the USB cable first.
  2. Press the button into the breadboard across the center gap.
  3. Run a wire from one button leg to pin D1.
  4. Connect the diagonally opposite leg to GND.

No external resistor is needed, because the code turns on INPUT_PULLUP: a resistor inside the chip that pulls D1 up to 3.3 V. So when the button is released the pin reads HIGH, and when it is pressed the pin is connected to GND and reads LOW.

Why debounce

The metal contacts inside a button bounce against each other several times in the first 1–5 ms of a press. If the code reads the pin directly, one press can count as several. The Debouncer fixes this by accepting a new state only after the signal has stayed stable for a set time (20 ms by default).

Hands-on

  1. Create a new sketch (File → New Sketch) and save it as button_count.
  2. Create src/Debouncer.h the same way as in lesson 05 (Sketch → Show Sketch Folder → create a src folder → create Debouncer.h) and paste the first code block below.
  3. Paste the second code block into button_count.ino and click Upload.
  4. Open Tools → Serial Monitor and set the speed at the right of the Serial Monitor panel to 115200 baud, to match Serial.begin(115200) in the code.
  5. Press the button a few times. presses should go up by exactly 1 each time.
src/Debouncer.h
#pragma once
#include <stdint.h>

// Pure logic: never calls the Arduino API, so it can be tested on a PC
class Debouncer {
public:
  enum class Event : uint8_t { None, Pressed, Released };

  explicit Debouncer(uint32_t stableMs = 20) : stableMs_(stableMs) {}

  // raw: true = pressed (already converted from active-LOW), nowMs: current time
  Event update(bool raw, uint32_t nowMs) {
    if (raw != lastRaw_) {  // still bouncing → restart the timer
      lastRaw_ = raw;
      changedAt_ = nowMs;
      return Event::None;
    }
    if (raw != stable_ && (nowMs - changedAt_) >= stableMs_) {
      stable_ = raw;
      return stable_ ? Event::Pressed : Event::Released;
    }
    return Event::None;
  }

  bool isPressed() const { return stable_; }

private:
  uint32_t stableMs_;
  uint32_t changedAt_ = 0;
  bool lastRaw_ = false;
  bool stable_ = false;
};
button_count.ino
#include "src/Debouncer.h"

constexpr uint8_t kButtonPin = D1;

Debouncer button;        // stableMs = 20 (default)
uint32_t presses = 0;

void setup() {
  Serial.begin(115200);
  pinMode(kButtonPin, INPUT_PULLUP);
}

void loop() {
  bool pressed = (digitalRead(kButtonPin) == LOW);   // active-LOW → true = pressed
  if (button.update(pressed, millis()) == Debouncer::Event::Pressed) {
    presses++;
    Serial.print("presses = ");
    Serial.println(presses);
  }
}

How the Debouncer works

  • update() is called on every pass of loop with the value just read (raw) and the current time (nowMs). There is no delay(), so loop stays free for other work.
  • If raw differs from the previous call, the contacts are still bouncing, so it stores the time in changedAt_ and starts counting again.
  • Once raw has been stable for stableMs_ and differs from the confirmed state (stable_), it switches state and returns Event::Pressed or Event::Released exactly once.
  • The class never calls millis() or digitalRead() itself; the caller passes the values in. That is what lets you test it on a PC in lesson 19.

Try changing Debouncer button; to Debouncer button(0); (no waiting at all) and upload again. Press the button and watch the count sometimes jump by several at once. That is the bounce the Debouncer filters out. Then change it back.

Check your understanding

Why is nowMs - changedAt_ still correct when millis() overflows (after about 49.7 days)?

Unsigned 32-bit subtraction is modulo 2³², so the difference is always right as long as the interval is under 49.7 days. Never write now > changedAt_ + stableMs_; that breaks on overflow.

Why not just call delay(20) after reading the button?

delay() stops the whole program, so nothing else can run (no sensor reads, no LED blinking), and short presses can still be missed. This Debouncer costs only a few microseconds per call.
