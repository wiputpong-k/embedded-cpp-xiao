CI 1: run tests automatically with GitHub Actions

30 min · Hardware: Computer

In this lesson
  1. Hands-on
  2. Make CI fail on purpose
  3. Check your understanding

Goal Every push and every PR is tested automatically on GitHub's servers

CI (Continuous Integration) means a machine checks the code on every change. GitHub Actions reads workflow files (written in YAML) in .github/workflows/, starts a temporary Linux machine (a runner) and runs the commands in them. This lesson starts with one job, host-tests, which runs the tests from lessons 19–20. The next lesson adds a job that compiles the firmware.

Hands-on

  1. In Git Bash, go into the repo, create a new branch and create the .github/workflows folder (the first 3 lines below).
  2. Run notepad .github/workflows/ci.yml, paste the ci.yml content below and save. YAML uses indentation as structure: use spaces, never Tab, and keep the indentation exactly as shown.
  3. Commit, push and open a PR, then run gh pr checks --watch to watch the job status live.
  4. Open the PR on the web, go to the Checks tab (or the repo's Actions tab), click the host-tests job and click each step to read its log.
  5. When it is green, merge the PR (gh pr merge --squash --delete-branch).
Git Bash
cd ~/xiao-embedded-cpp
git switch -c ci/host-tests
mkdir -p .github/workflows
# paste ci.yml and save, then:
git add .github/
git commit -m "ci: run host tests on every push and PR"
git push -u origin ci/host-tests
gh pr create --fill
gh pr checks --watch        # watch job status live
.github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:

jobs:
  host-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build tests
        run: g++ -std=c++17 -Wall -Wextra -Werror -Ifirmware/src test/test_main.cpp -o test_runner
      - name: Run tests
        run: ./test_runner
      - name: Static analysis
        run: |
          sudo apt-get update && sudo apt-get install -y cppcheck
          cppcheck --error-exitcode=1 --enable=warning,performance --std=c++17 -Ifirmware/src test/test_main.cpp

Make CI fail on purpose

Create a new branch, change >= to > in Debouncer.h as in lesson 20, push and open a PR. The PR shows a red cross; open the log of the Run tests step and you see the same FAIL line you saw locally. Then close that PR with gh pr close --delete-branch.

Check your understanding

The GitHub runner is Linux and your PC is Windows. Why do the tests give the same result?

Because the code under test is plain standard C++ that does not depend on the OS or hardware. That is another benefit of separating logic from hardware in lesson 19.

Why does the job turn red when a test fails?

./test_runner returns exit code 1 when any CHECK fails. GitHub Actions treats any step that returns non-zero as failed and stops the job.
