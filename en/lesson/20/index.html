Write your own unit tests

25 min · Hardware: Computer

Goal Understand how test_main.cpp works, make a test fail on purpose, and add a new test yourself

How test_main.cpp works

  • CHECK(cond) is a macro. If cond is false, it prints the file name (__FILE__), the line number (__LINE__) and the condition as text (#cond), and counts the failure.
  • It is wrapped in do { … } while (0) so the macro behaves like a single statement, even inside an if without braces.
  • Each test is its own function (test_ringbuffer, test_debouncer). main() calls them all and returns an exit code based on the result.
  • test_debouncer feeds in fake times of 0, 5, 8, 20 and 28 ms, so it tests bouncing precisely every time, which is almost impossible to do by hand on a real board.

Hands-on 1: make a test fail

  1. Open firmware/src/Debouncer.h and change >= stableMs_ to > stableMs_.
  2. Compile and run the tests again (same commands as lesson 19). You see a FAIL … line with the file and line number, and no ALL TESTS PASSED.
  3. Run echo $? right after the test run. It prints 1, the failure exit code.
  4. Change it back to >= and run again until it passes.

Hands-on 2: add your own tests

Add the functions below above main() in test/test_main.cpp, then add test_average_empty(); and test_debouncer_release(); to main() after the existing tests. Make them pass, then commit.

test/test_main.cpp
static void test_average_empty() {
  RingBuffer<int, 4> rb;
  CHECK(average(rb) == 0.0f);      // empty → 0, no divide by zero
}

static void test_debouncer_release() {
  using E = Debouncer::Event;
  Debouncer d(20);
  d.update(true, 0);
  CHECK(d.update(true, 20) == E::Pressed);
  CHECK(d.update(false, 30) == E::None);      // just released, not stable yet
  CHECK(d.update(false, 50) == E::Released);  // stable for 20 ms
  CHECK(!d.isPressed());
}

Real projects use a framework such as GoogleTest, Catch2 or Unity (for C), but the idea is the same: CHECK a condition, report the failing line, and exit with a non-zero code on failure so CI knows.

Check your understanding

How do you test code that calls digitalRead()?

Hide hardware access behind an interface (like ISensor in lesson 09) and plug in a fake/mock for tests, or pass the value in instead of letting the function read it.

What makes a good test?

Fast, gives the same result every run, tests one thing, and reads clearly as an expectation. Include edge cases such as an empty buffer, a full buffer and time overflow.

In practice

Most firmware teams test in layers: host unit tests for logic, HIL tests on real boards for drivers, and system tests for features. The first layer is the fastest and cheapest, so it runs in CI on every commit.
