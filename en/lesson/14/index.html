Mini project 2: commands over Serial

25 min · Hardware: LED + button + pot

In this lesson
  1. Hands-on
  2. Check your understanding

Goal Add non-blocking command input from Serial Monitor to the firmware from the previous lesson

Real firmware often takes commands from outside, such as settings or test triggers. The catch is that text arrives one character at a time. If you wait for a whole line with something like Serial.readStringUntil(), loop stalls while it waits and every other task stops.

handleSerial() avoids this by reading only the characters that have already arrived, collecting them in a buffer, and returning right away. When it sees a line ending (\n or \r), it converts the text to a number and uses it.

  • static makes buf and len keep their values between calls (lesson 11), so half a line is not lost.
  • len < sizeof(buf) - 1 stops writes past the end of the buffer and leaves one slot for \0.
  • Always check the range (50–5000) before using the value. Never trust outside input unchecked.

Hands-on

  1. Open the firmware sketch from the previous lesson and replace all of its code with the code below (it adds handleSerial() and calls it on the last line of loop()).
  2. Click Upload, then open Tools → Serial Monitor at 115200 baud.
  3. At the right of the Serial Monitor there is a line-ending option. Pick New Line, otherwise the board never knows you finished typing a line.
  4. Type 100 in the message box at the top of the Serial Monitor and press Enter. The green LED should blink faster. Try 2000, then 10 (out of range, so nothing should change).
firmware/firmware.ino
#include <Adafruit_TinyUSB.h>   // enables USB and Serial (required by this core)
#include "src/Led.h"
#include "src/Debouncer.h"
#include "src/RingBuffer.h"

#if __has_include("src/version.h")
#include "src/version.h"          // generated by CI (lesson 23)
#else
#define FW_VERSION "dev"
#endif

constexpr uint8_t kButtonPin = D1;
constexpr uint8_t kPotPin    = A0;

Led status(LED_GREEN, true);
Led ext(D2, false);
Debouncer button;
xiao::RingBuffer<uint16_t, 16> samples;
bool paused = false;

struct Task {
  uint32_t periodMs;
  uint32_t lastRunMs;
  void (*run)();
};

void blinkTask() { if (!paused) status.toggle(); }

void buttonTask() {
  bool pressed = digitalRead(kButtonPin) == LOW;
  if (button.update(pressed, millis()) == Debouncer::Event::Pressed) {
    paused = !paused;
    ext.toggle();
  }
}

void sensorTask() { samples.pushOverwrite(analogRead(kPotPin)); }

void reportTask() {
  Serial.print("avg:");     Serial.print(average(samples));
  Serial.print(" paused:"); Serial.println(paused ? 1 : 0);
}

Task tasks[] = {
  {500, 0, blinkTask},
  {5,   0, buttonTask},
  {20,  0, sensorTask},
  {200, 0, reportTask},
};

// type 50–5000 and press Enter to change the blink period
void handleSerial() {
  static char buf[16];
  static size_t len = 0;
  while (Serial.available()) {
    char c = Serial.read();
    if (c == '\n' || c == '\r') {
      if (len > 0) {
        buf[len] = '\0';
        long ms = atol(buf);
        if (ms >= 50 && ms <= 5000) tasks[0].periodMs = ms;
        len = 0;
      }
    } else if (len < sizeof(buf) - 1) {
      buf[len++] = c;
    }
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(kButtonPin, INPUT_PULLUP);
  status.begin();
  ext.begin();
  Serial.print("fw "); Serial.println(FW_VERSION);
}

void loop() {
  uint32_t now = millis();
  for (Task& t : tasks) {
    if (now - t.lastRunMs >= t.periodMs) {
      t.lastRunMs = now;
      t.run();
    }
  }
  handleSerial();
}

The #if __has_include("src/version.h") line checks whether version.h exists. It does not yet, so the program prints fw dev at startup. In lesson 23, CI generates this file with the real version number automatically.

Check your understanding

What happens if you type more than 15 characters?

The extra characters are dropped, because len never grows past sizeof(buf) - 1. The program does not crash or overwrite other memory, and the resulting number is still range-checked.

Why check for both \n and \r?

Different terminal programs send different line endings: \n, \r, or both. Accepting either, and skipping empty lines (len == 0), makes it work with all of them.
