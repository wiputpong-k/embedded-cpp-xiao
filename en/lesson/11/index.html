Memory in embedded systems

25 min · Hardware: Board only

In this lesson
  1. Hands-on
  2. Rules real teams use
  3. Check your understanding

Goal Know where each kind of variable lives, and the rules real firmware teams follow

Hands-on

memmap.ino
uint8_t bigStatic[8192];        // .bss  → counted in "Global variables use"
const char kMsg[] = "hello";    // .rodata → lives in flash

void setup() {
  Serial.begin(115200);
  while (!Serial) {}
  uint8_t onStack[256];         // stack → not in the compile-time numbers
  onStack[0] = 1;
  bigStatic[0] = onStack[0];
  Serial.print("flash  : 0x"); Serial.println((uintptr_t)kMsg, HEX);
  Serial.print("static : 0x"); Serial.println((uintptr_t)bigStatic, HEX);
  Serial.print("stack  : 0x"); Serial.println((uintptr_t)onStack, HEX);
}

void loop() {}

Check that the addresses start with 0x000… (flash) or 0x2000… (RAM) as in the diagram. Then change bigStatic to 32768 and watch the RAM figure change at compile time.

Rules real teams use

  • Allocate memory at init only. Never new/malloc in the loop afterwards: the heap fragments and the device fails after days of running.
  • Avoid Arduino's String; use char buf[32] + snprintf instead.
  • Use std::array / fixed-size buffers, and avoid std::vector and std::function, which may allocate on the heap.
  • Embedded builds often disable exceptions and RTTI (-fno-exceptions -fno-rtti), so errors are handled with return values.

Check your understanding

Where does a static variable inside a function live?

In .data or .bss like a global, but its scope is limited to the function, so it keeps its value between calls.

What does a stack overflow look like on an MCU without an OS?

The stack grows down into the heap or .bss, causing random variable corruption or a HardFault. Detect it with stack painting (fill a pattern and see how deep it gets overwritten) or an MPU guard region.

In practice

Reach for this memory map whenever you hit a HardFault or run out of RAM: find which of .text / .data / .bss / heap / stack the faulting address falls in, and open the linker .map file to see what uses the most space.
