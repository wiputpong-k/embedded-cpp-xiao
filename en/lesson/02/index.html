Reference, const and constexpr instead of #define

25 min · Hardware: Board only

In this lesson
  1. Hands-on
  2. Check your understanding

Goal Stop using #define for constants, and pass parameters by reference in the right places

In C, constants are often #define LED_COUNT 3. The preprocessor (the first build stage from lesson 01) simply replaces the text LED_COUNT with 3 before compiling, so the value has no type and no scope. C++ has a better way, plus references, which replace pointers in many cases.

C

Constants use #define: no type, no scope. To change the caller's variable you pass a pointer.

C++

constexpr has a type and is computed at compile time, using no RAM. T& is an alias for an existing variable: never null, no * needed.

  • compile time / runtime: a value known while compiling (on the PC, before the board) versus one known only while the program runs on the board. A compile-time value needs no work on the chip and no RAM.
  • scope: the region where a name can be used, e.g. inside a function's { }. #define ignores scope: it applies to the rest of the file.
  • reference (T&): a second name for an existing variable. Changing it changes the original, like passing a pointer, but with no & at the call and no * when using it.

Hands-on

This sketch proves three things: constexpr can size an array and is computed at compile time, a reference changes the caller's variable without a pointer, and const lets the compiler catch bugs for you.

  1. Create a new sketch (File → New Sketch), paste the code below, and save it as rgb_cycle.
  2. Press Upload. Expected result: the on-board LED cycles red → green → blue every 0.15 s.
rgb_cycle.ino
#include <Adafruit_TinyUSB.h>   // enables USB and Serial (required by this core)
constexpr uint8_t kLedPins[] = {LED_RED, LED_GREEN, LED_BLUE};
constexpr size_t  kLedCount  = sizeof(kLedPins) / sizeof(kLedPins[0]);
constexpr uint32_t kStepMs   = 150;

void allOff() {
  for (uint8_t pin : kLedPins) {   // range-based for (C++11)
    digitalWrite(pin, HIGH);
  }
}

void nextIndex(size_t& idx) {      // reference: changes the caller's variable directly
  idx = (idx + 1) % kLedCount;
}

size_t current = 0;

void setup() {
  for (uint8_t pin : kLedPins) pinMode(pin, OUTPUT);
  allOff();
}

void loop() {
  allOff();
  digitalWrite(kLedPins[current], LOW);
  delay(kStepMs);
  nextIndex(current);
}
  • uint8_t, uint32_t: types with an explicit size (8 and 32 bits); size_t is for counts and sizes. They replace int, whose size depends on the board (lesson 01).
  • for (uint8_t pin : kLedPins) is C++11's range-based for: it visits every element of the array without an index.
  • HIGH = off and LOW = on, because the on-board LED is active-LOW (lesson 00).

What the result tells you:

  • reference: the colour changes because nextIndex(current) modifies the real current. In C you would write nextIndex(&current) and *idx = ....
  • constexpr: kLedCount = 3 is computed at compile time from sizeof. Add a pin to kLedPins and it follows without editing a number.

Try const: add this function above setup() and press Verify.

add to rgb_cycle.ino
#include <Adafruit_TinyUSB.h>   // enables USB and Serial (required by this core)
void printPin(const uint8_t& p) {
  p = 0;
}

The compiler refuses with error: assignment of read-only reference 'p'. That is what const buys you: the bug is caught at compile time, not while the board runs. (const uint8_t& is only for this experiment; small types like this are normally passed by value, see the first question below.) Delete the function afterwards.

Check your understanding

When should you pass const T& instead of by value?

When T is bigger than a register (a 32-bit storage slot inside the CPU), such as a struct or buffer, to avoid a copy. Pass int, float and pointers by value: faster and easier to read.

How does constexpr differ from const?

const means read-only, but the value may only be known at runtime. constexpr must be known at compile time, so it can size an array (and feed templates, lesson 10).

In practice

In firmware code reviews, #define constants are often sent back to become constexpr: #define has no type checking, ignores namespaces and scope, is invisible to the debugger, and macro expansion can cause side effects.
