Reference, const and constexpr instead of #define

25 min · Hardware: Board only

In this lesson
  1. Hands-on
  2. Check your understanding

Goal Stop using #define for constants, and pass parameters by reference in the right places

C

Constants use #define: no type, no scope. To change the caller's variable you pass a pointer.

C++

constexpr has a type and is computed at compile time, using no RAM. T& is an alias for an existing variable: never null, no * needed.

Hands-on

rgb_cycle.ino
constexpr uint8_t kLedPins[] = {LED_RED, LED_GREEN, LED_BLUE};
constexpr size_t  kLedCount  = sizeof(kLedPins) / sizeof(kLedPins[0]);
constexpr uint32_t kStepMs   = 150;

void allOff() {
  for (uint8_t pin : kLedPins) {   // range-based for (C++11)
    digitalWrite(pin, HIGH);
  }
}

void nextIndex(size_t& idx) {      // reference: changes the caller's variable directly
  idx = (idx + 1) % kLedCount;
}

size_t current = 0;

void setup() {
  for (uint8_t pin : kLedPins) pinMode(pin, OUTPUT);
  allOff();
}

void loop() {
  allOff();
  digitalWrite(kLedPins[current], LOW);
  delay(kStepMs);
  nextIndex(current);
}

Add a function void printPin(const uint8_t& p) and try writing p = 0; inside it. Read the compiler error. That is what const buys you: bugs caught at compile time.

Check your understanding

When should you pass const T& instead of by value?

When T is bigger than a register (structs, buffers), to avoid a copy. Pass int, float and pointers by value: faster and easier to read.

How does constexpr differ from const?

const means read-only, but the value may only be known at runtime. constexpr must be known at compile time, so it can size an array or be a template argument.

In practice

In firmware code reviews, #define constants are often sent back to become constexpr: #define has no type checking, ignores namespaces and scope, is invisible to the debugger, and macro expansion can cause side effects.
