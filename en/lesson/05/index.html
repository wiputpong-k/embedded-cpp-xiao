Split code into files: headers and src/

25 min · Hardware: LED + R 1 kΩ

In this lesson
  1. Hands-on
  2. Check your understanding

Goal Move the Led class into src/Led.h so later lessons can reuse it

C

Split into .h (declarations) and .c (function bodies), and guard against double includes with #ifndef.

C++

A class whose member functions are written inside the class body can live in a single .h, because those functions are implicitly inline. One line of #pragma once guards against double includes.

As a project grows, keeping everything in one .ino file gets hard to read and impossible to reuse. Arduino automatically compiles every file in a src/ folder inside the sketch folder, so from this lesson through lesson 13 the course keeps reusable classes in src/.

Arduino IDE 2 only shows tabs for files at the top level of the sketch folder. Files in src/ do not appear as tabs, so edit them with another program such as VS Code or Notepad. The IDE still compiles them as usual.

Hands-on

  1. Open the led_class sketch from the previous lesson (File → Open… or File → Sketchbook).
  2. Click Sketch → Show Sketch Folder. The sketch folder opens in File Explorer.
  3. If you cannot see file extensions, turn them on in File Explorer: View → Show → File name extensions.
  4. Create a new folder named src and open it. Right-click, choose New → Text Document, and rename it to Led.h (remove the .txt too). If Windows asks about changing the extension, click Yes.
  5. Right-click Led.h, open it with VS Code or Notepad, paste the src/Led.h code below and save.
  6. Back in Arduino IDE, replace everything in led_class.ino with the second code block below and click Upload. It should behave exactly like the previous lesson.
src/Led.h
#pragma once
#include <Arduino.h>

class Led {
public:
  Led(uint8_t pin, bool activeLow) : pin_(pin), activeLow_(activeLow) {}

  void begin() { pinMode(pin_, OUTPUT); off(); }
  void on()     { write(true); }
  void off()    { write(false); }
  void toggle() { write(!isOn_); }
  bool isOn() const { return isOn_; }   // const method: does not change state

private:
  void write(bool on) {
    isOn_ = on;
    digitalWrite(pin_, (on != activeLow_) ? HIGH : LOW);
  }
  uint8_t pin_;
  bool activeLow_;
  bool isOn_ = false;
};
led_class.ino
#include "src/Led.h"

Led red(LED_RED, true);   // on-board: active-LOW
Led ext(D2, false);       // external: active-HIGH

void setup() {
  red.begin();
  ext.begin();
}

void loop() {
  red.toggle();
  ext.toggle();
  delay(300);
}

#include "src/Led.h" uses quotes, which means "look in the sketch folder first". #include <Arduino.h> uses angle brackets, which means "look in the installed libraries and core". Led.h has to include Arduino.h itself, because the IDE only adds it to .ino files.

Check your understanding

What happens if you remove #pragma once and Led.h ends up included twice through other headers?

The compiler sees class Led defined twice in one translation unit and reports a redefinition error. #pragma once (or an #ifndef guard) makes the file be read only once.

Why can Led.h contain function bodies and be included from several .cpp files without a multiple-definition error?

Member functions defined inside the class body are implicitly inline, so the linker accepts the copies and keeps one. A plain function written outside a class in a .h needs inline added by hand.

In practice

The "static initialization order fiasco" is a real bug in multi-file projects: the construction order of global objects across files is unspecified, so one object may use another that does not exist yet. The fixes are begin() or a function-local static.
