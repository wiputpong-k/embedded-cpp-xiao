CD: automatic firmware releases from tags

30 min · Hardware: Board + computer

In this lesson
  1. Step 1: Add the release workflow
  2. Step 2: Tag and push
  3. Step 3: Flash the Release file onto the board
  4. Check your understanding

Goal Push a tag, get a GitHub Release with the firmware files and the version number built in, and flash that file onto the board

CD (Continuous Delivery) means delivering ready-to-use files automatically. The workflow in this lesson runs when you push a tag starting with v, such as v0.1.0. It writes version.h from the tag name, compiles the firmware, and creates a GitHub Release page with the files attached for download.

Step 1: Add the release workflow

main only accepts changes through PRs (lesson 18), so add this file through a PR as before. Create .github/workflows/release.yml with the content below, then run the next set of commands.

.github/workflows/release.yml
name: Release

on:
  push:
    tags: ['v*.*.*']

permissions:
  contents: write

env:
  BOARD_URL: https://files.seeedstudio.com/arduino/package_seeeduino_boards_index.json
  FQBN: Seeeduino:nrf52:xiaonRF52840Sense

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      - run: pip install adafruit-nrfutil
      - uses: arduino/setup-arduino-cli@v2
      - run: |
          arduino-cli core update-index --additional-urls "$BOARD_URL"
          arduino-cli core install Seeeduino:nrf52 --additional-urls "$BOARD_URL"
      - name: Stamp version
        run: echo "#define FW_VERSION \"${GITHUB_REF_NAME}\"" > firmware/src/version.h
      - name: Compile
        run: arduino-cli compile --fqbn "$FQBN" --additional-urls "$BOARD_URL" --output-dir out firmware
      - uses: softprops/action-gh-release@v2
        with:
          files: |
            out/*.hex
            out/*.zip
          generate_release_notes: true
Git Bash
git switch -c ci/release
git add .github/workflows/release.yml
git commit -m "ci: release firmware on version tag"
git push -u origin ci/release
gh pr create --fill
gh pr checks --watch
gh pr merge --squash --delete-branch
git switch main
git pull

Step 2: Tag and push

A tag is a label attached to one commit, saying which version it is. Pushing a tag does not need a PR. After the push, open the Actions tab and watch the Release workflow run. When it finishes there is a new Release page (gh release view --web).

Git Bash
git tag -a v0.1.0 -m "first release: scheduler, debounce, moving average"
git push origin v0.1.0
gh release view --web

Step 3: Flash the Release file onto the board

The XIAO nRF52840 takes firmware through its bootloader as a .zip (DFU package), not as a raw .hex. Arduino IDE does this for you on every Upload; for a file from a Release you use the adafruit-nrfutil tool.

  1. If you do not have Python yet, install it first (the first command below, in PowerShell), close the terminal and open it again. Then install adafruit-nrfutil with pip.
  2. In Git Bash, download the .zip from the Release (named something like firmware.ino.zip).
  3. Double-press the reset button on the board to enter the bootloader, and check the port number in Arduino IDE under Tools → Port (e.g. COM5).
  4. Run the adafruit-nrfutil command with COM5 replaced by your port, and wait for "Device programmed".
  5. Open Serial Monitor (115200 baud) and press reset once. You should see fw v0.1.0 (a build from your local IDE shows fw dev).
PowerShell
winget install -e --id Python.Python.3.12
pip install adafruit-nrfutil
Git Bash
gh release download v0.1.0 --pattern "*.zip"
adafruit-nrfutil --verbose dfu serial --package firmware.ino.zip -p COM5 -b 115200 --singlebank

This is traceability: you always know which firmware version each board runs, and the tag takes you back to that version's code.

SemVer: MAJOR.MINOR.PATCH. Bug fix → +PATCH, backward-compatible feature → +MINOR, breaking change (e.g. a protocol) → +MAJOR. If you want a .uf2 to drag onto the drive that appears after a double-tap reset, convert the .hex with uf2conv.py (family 0xADA52840).

Check your understanding

Why generate version.h in CI instead of writing the version in the code?

The tag becomes the single source of truth, so you cannot forget to bump the number, and local builds say "dev", clearly not a release.

Is permissions: contents: write required?

Yes. In many repos the default GITHUB_TOKEN is read-only, and creating a Release needs write access.
