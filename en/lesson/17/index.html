GitHub: create a repo and push

30 min · Hardware: Computer

Goal Set up the GitHub CLI and push your local repo to GitHub for the first time

GitHub is a website that hosts Git repos on a server. You use it to share code with a team, and it is where CI (lesson 21) runs. The GitHub CLI (gh) lets you drive GitHub from the terminal, for example creating a repo or opening a Pull Request without clicking around the website.

Step 1: Create a GitHub account

If you do not have an account yet, sign up at github.com/signup and confirm your email. If you already have one, skip this step.

Step 2: Install the GitHub CLI

  1. Open PowerShell and run the first command below (winget comes with Windows 10/11), or download the installer from cli.github.com.
  2. Close PowerShell, open it again, and run gh --version. You should see a version number.
PowerShell
winget install --id GitHub.cli
gh --version

Step 3: Log in once

Run gh auth login and answer the prompts like this (use the arrow keys, then Enter):

  1. Where do you use GitHub? → GitHub.com
  2. What is your preferred protocol for Git operations? → HTTPS
  3. Authenticate Git with your GitHub credentials? → Yes
  4. How would you like to authenticate GitHub CLI? → Login with a web browser
  5. The terminal shows an 8-character one-time code. Note it and press Enter. Your browser opens a GitHub page; enter the code there and click Authorize.

Check: run gh auth status. It should say you are logged in to github.com with your account name.

PowerShell
gh auth login
gh auth status

Step 4: Create the repo on GitHub and push

Go into the repo folder from lesson 15 and run the commands below. gh repo create creates a repo of the same name on GitHub, names the remote origin, and pushes all your commits in one go.

terminal
cd ~/xiao-embedded-cpp
gh repo create xiao-embedded-cpp --public --source=. --remote=origin --push
gh repo view --web          # open the repo page in your browser

Check: the repo page on GitHub shows the firmware/ folder and .gitignore, and the Commits view lists your commits from lessons 15–16. From now on, after you commit locally, run git push to send it to GitHub.

Check your understanding

How do fetch and pull differ?

fetch downloads the remote state (origin/main) without touching your branch. pull = fetch + merge (or rebase) into your branch.

What is origin?

A short name for the URL of the repo on the server. Any name works, but origin is the convention for the main remote. See it with git remote -v.
