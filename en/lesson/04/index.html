Goal Wire an external LED, and write a Led class that hides the active-LOW detail inside

C

A struct holds the data and a separate function led_on(&led) acts on it. Anyone can change the fields.

C++

Data (private) and behavior (public) live together. The compiled code is about the same size, because this is just a hidden pointer argument.

Wire it up

A breadboard lets you connect parts without soldering. The 5 holes in each short row (across the center gap) are connected inside. The long rows along the edges, marked red and blue, are the power and GND rails.

  1. Always unplug the USB cable before you change the wiring.
  2. Press the XIAO into the breadboard across the center gap, so the two rows of pins are on opposite sides. (If the board has no header pins soldered yet, solder them first.)
  3. Find the LED polarity: the long leg is positive (anode), the short leg is negative (cathode), and the flat edge on the LED rim marks the negative side.
  4. Run a jumper wire from pin D2 to one leg of the 1 kΩ resistor (resistors have no polarity).
  5. Connect the other resistor leg to the LED's long leg.
  6. Connect the LED's short leg to the board's GND pin.

If the LED does not light, try flipping it first; that is the most common cause. The 1 kΩ resistor limits the current. Never connect an LED straight to a pin without it.

Hands-on

  1. Plug the USB cable back in and open File → New Sketch.
  2. Copy the code below over the starter code, then File → Save As… and name it led_class.
  3. Click Upload. Both the red on-board LED and the external LED should blink together every 0.3 s.
led_class.ino
class Led {
public:
  Led(uint8_t pin, bool activeLow) : pin_(pin), activeLow_(activeLow) {}

  void begin() { pinMode(pin_, OUTPUT); off(); }
  void on()     { write(true); }
  void off()    { write(false); }
  void toggle() { write(!isOn_); }
  bool isOn() const { return isOn_; }   // const method: does not change state

private:
  void write(bool on) {
    isOn_ = on;
    digitalWrite(pin_, (on != activeLow_) ? HIGH : LOW);
  }
  uint8_t pin_;
  bool activeLow_;
  bool isOn_ = false;
};

Led red(LED_RED, true);   // on-board: active-LOW
Led ext(D2, false);       // external: active-HIGH

void setup() {
  red.begin();
  ext.begin();
}

void loop() {
  red.toggle();
  ext.toggle();
  delay(300);
}

Notice that both LEDs light at the same time, even though the on-board LED is active-LOW and the external one is active-HIGH. The class handles that inside write(); callers just use on() or toggle() without knowing how the LED is wired.

Why a separate begin() instead of calling pinMode in the constructor? Global objects are constructed before main() and before init(), so the hardware may not be ready yet. This is a standard embedded C++ pattern.

Check your understanding

Why is a member initializer list (: pin_(pin)) better than assigning in the body?

Members are constructed with the right value from the start instead of being default-constructed and then assigned. It is required for const and reference members.

Roughly how many bytes of RAM does a Led object use?

About 3–4 bytes (pin_, activeLow_, isOn_ + padding). Member functions cost no RAM per object; they live in flash and are shared.
