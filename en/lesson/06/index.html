RAII and destructors

30 min · Hardware: 10 kΩ pot on A0

In this lesson
  1. Wire it up
  2. Hands-on
  3. Check your understanding

Goal Let scope manage resources automatically: timing, disabling/enabling interrupts

In C, if you disable interrupts and then return from the middle of a function without re-enabling them, the system hangs in a way that is hard to trace. C++ solves this by tying the "give back" step to leaving a { } block. Terms used in this lesson:

  • resource: something you borrow and must give back, e.g. the "interrupts disabled" state, a lock, or a reserved buffer.
  • interrupt: a signal that makes the CPU pause its current work to handle something urgent, e.g. USB data arriving (lesson 12 goes deeper). Sometimes they must be turned off briefly so code is not cut in the middle; that stretch is a critical section.
  • destructor: the function ~ClassName() that runs automatically when an object ends its life. A local object ends when execution leaves the { } that declared it (scope, lesson 02).

RAII (Resource Acquisition Is Initialization): acquire the resource in the constructor and release it in the destructor. The compiler always calls the destructor when the object leaves scope, so you can never forget unlock or re-enabling interrupts, even if you return early. C has no such mechanism.

Wire it up

A potentiometer (pot) is an adjustable resistor with 3 legs. The outer legs connect to the two ends of the resistor; the middle leg (wiper) slides along it as you turn the knob, so the voltage on the middle leg can go from 0 to 3.3 V.

  1. Unplug the USB cable first (the LED from lesson 04 can stay).
  2. Press the pot into the breadboard with its 3 legs in different rows.
  3. Connect one outer leg to the board's 3V3 pin and the other outer leg to GND (either way round; it only flips the turning direction).
  4. Connect the middle leg to pin A0 (the same pin as D0).

Use 3V3 only, never 5V: the nRF52840's pins accept at most 3.3 V.

Hands-on

This sketch proves that destructors run by themselves when execution leaves a { }: ScopedTimer prints the time though nobody calls print, and CriticalSection re-enables interrupts though no line does it.

  1. Plug USB back in, create a new sketch, paste the code below, save it as raii, and press Upload.
  2. Open Tools → Serial Monitor at 115200 baud and turn the pot.
raii.ino
#include <Adafruit_TinyUSB.h>   // enables USB and Serial (required by this core)
class ScopedTimer {
public:
  explicit ScopedTimer(const char* label) : label_(label), start_(micros()) {}
  ~ScopedTimer() {
    uint32_t us = micros() - start_;
    Serial.print(label_); Serial.print(": "); Serial.print(us); Serial.println(" us");
  }
  ScopedTimer(const ScopedTimer&) = delete;             // no copying
  ScopedTimer& operator=(const ScopedTimer&) = delete;
private:
  const char* label_;
  uint32_t start_;
};

// Nestable interrupt disable: save the previous state, then restore it
class CriticalSection {
public:
  CriticalSection() : primask_(__get_PRIMASK()) { __disable_irq(); }
  ~CriticalSection() { __set_PRIMASK(primask_); }
private:
  uint32_t primask_;
};

void setup() { Serial.begin(115200); }

void loop() {
  long sum = 0;
  {
    ScopedTimer t("analogRead x100");
    for (int i = 0; i < 100; ++i) sum += analogRead(A0);
  }                                   // destructor runs here
  Serial.print("avg = "); Serial.println(sum / 100);

  uint32_t inside;
  {
    CriticalSection cs;               // interrupts off
    inside = __get_PRIMASK();         // 1 = disabled
  }                                   // destructor turns them back on
  Serial.print("PRIMASK inside = "); Serial.print(inside);
  Serial.print(", after = ");        Serial.println(__get_PRIMASK());
  delay(1000);
}
  • micros(): time since the board started, in microseconds.
  • explicit stops the compiler from silently turning a string into a ScopedTimer. = delete forbids that function (here: no copying, see the first question).
  • PRIMASK: a register in the Cortex-M CPU: 1 = interrupts off, 0 = on. __disable_irq() sets it to 1; __get_PRIMASK() / __set_PRIMASK() read and write it.

Expected output every second (your us and avg numbers will differ):

Serial Monitor
analogRead x100: … us
avg = 512
PRIMASK inside = 1, after = 0

What the output tells you:

  • Destructors run by themselves: nothing in loop() prints the analogRead x100 line. It comes from ~ScopedTimer(), running at the }.
  • The resource is always returned: inside = 1 means interrupts were off inside the { }, and after = 0 means they are back on, with no line that turns them on.
  • Pot wiring: turning the pot moves avg between 0 and 1023, because analogRead() uses the ADC (a circuit in the chip that turns a voltage into a number) to map 0–3.3 V to 0–1023.

Never call Serial.print while interrupts are off, because USB needs interrupts. That is why the value is stored first and printed after the { }.

Check your understanding

Why = delete the copy constructor?

If copying were allowed, two objects would run the destructor, e.g. re-enabling interrupts twice or printing the time twice. A resource with a single owner should not be copyable.

Can CriticalSection be used while BLE is running?

Only for a very short time, a few microseconds. BLE on the nRF52 runs through the SoftDevice (Nordic's radio software inside the chip); if interrupts stay off longer, it misses radio timing. Real projects use the SoftDevice's own function (sd_nvic_critical_region_enter) instead.

In practice

RAII is a main reason many teams move from C to C++ in embedded work: it costs no speed, and it removes a whole class of forgot-to-give-back bugs, such as not re-enabling interrupts on the path that exits early because of an error.
