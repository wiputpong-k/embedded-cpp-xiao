Module 0 · Setup

Install the tools + first Blink

30 min · Hardware: Board only

Goal The IDE compiles and flashes the board, and you know the on-board LED is active-LOW

Install

  1. Install Arduino IDE 2 and Git (Windows: Git for Windows, with VS Code as the editor)
  2. File → Preferences → Additional boards manager URLs, add
    https://files.seeedstudio.com/arduino/package_seeeduino_boards_index.json
  3. In Boards Manager, search Seeed nRF52 Boards (the one without "mbed") and install it → select the board Seeed XIAO nRF52840 Sense
  4. Also install arduino-cli for the CI lessons, then run arduino-cli board listall xiao and note the FQBN it prints

We use the non-mbed core because it builds faster and works with Adafruit's BLE library. If upload fails, double-press reset quickly to enter the bootloader, then select the new port.

Hands-on

blink.ino
// The on-board LED anode is tied to 3V3, so it lights when you write LOW
void setup() {
  pinMode(LED_RED, OUTPUT);
  digitalWrite(LED_RED, HIGH);   // off
}

void loop() {
  digitalWrite(LED_RED, LOW);    // on
  delay(200);
  digitalWrite(LED_RED, HIGH);   // off
  delay(800);
}

Try LED_GREEN / LED_BLUE, then turn on Preferences → Show verbose output during compile to see the compiler commands the IDE actually runs.

Check your understanding

Why does LED_RED light when you write LOW?

The LED is active-LOW: its anode sits at 3V3 and the GPIO pin sinks the current, so current flows when the pin is LOW.

Why use the non-mbed core in this course?

It builds faster, supports Bluefruit BLE and is easy to compile in CI. Both cores run the same C++.

Module A · C++ for C programmers

.ino is C++, and the path from code to board

20 min · Hardware: Board only

Goal See what Arduino hides from you, and the real toolchain

A .ino file is not a special language. The IDE only adds #include <Arduino.h> and function prototypes, then hands the file to arm-none-eabi-g++ to compile as ordinary C++. main() lives in the core:

core/main.cpp (trimmed)
int main() {
  init();          // clock, timer, USB CDC
  setup();
  for (;;) {
    loop();
  }
}

Hands-on

whoami.ino
void setup() {
  Serial.begin(115200);
  while (!Serial) {}             // wait for USB CDC
  Serial.print("__cplusplus = ");  Serial.println(__cplusplus);
  Serial.print("sizeof(int) = ");  Serial.println(sizeof(int));
  Serial.print("sizeof(void*) = ");Serial.println(sizeof(void*));
  Serial.print("sizeof(bool) = "); Serial.println(sizeof(bool));
}

void loop() {}

__cplusplus tells you the language standard the compiler uses (e.g. 201103 = C++11, 201703 = C++17). Note it down, because the features you can use depend on it. Then read the last lines of the output: Sketch uses … bytes = flash, Global variables use … = static RAM.

Check your understanding

If __cplusplus is 201103, can you use if constexpr?

No. if constexpr is C++17. Add -std=gnu++17 or fall back to template overloads.

Does "Global variables use" include the stack?

No. It counts only .data + .bss, whose sizes are known at link time. Local variables on the stack are not in that number.

Interview angle

A common question is "walk me through a firmware build". Answer in order: preprocess → compile → link (the linker script sets the addresses) → objcopy → flash, and mention that the .elf carries debug symbols while the .hex/.bin is the image that goes onto the chip.

Module A · C++ for C programmers

Reference, const and constexpr instead of #define

25 min · Hardware: Board only

Goal Stop using #define for constants, and pass parameters by reference in the right places

C

Constants use #define: no type, no scope. To change the caller's variable you pass a pointer.

C++

constexpr has a type and is computed at compile time, using no RAM. T& is an alias for an existing variable: never null, no * needed.

Hands-on

rgb_cycle.ino
constexpr uint8_t kLedPins[] = {LED_RED, LED_GREEN, LED_BLUE};
constexpr size_t  kLedCount  = sizeof(kLedPins) / sizeof(kLedPins[0]);
constexpr uint32_t kStepMs   = 150;

void allOff() {
  for (uint8_t pin : kLedPins) {   // range-based for (C++11)
    digitalWrite(pin, HIGH);
  }
}

void nextIndex(size_t& idx) {      // reference: changes the caller's variable directly
  idx = (idx + 1) % kLedCount;
}

size_t current = 0;

void setup() {
  for (uint8_t pin : kLedPins) pinMode(pin, OUTPUT);
  allOff();
}

void loop() {
  allOff();
  digitalWrite(kLedPins[current], LOW);
  delay(kStepMs);
  nextIndex(current);
}

Add a function void printPin(const uint8_t& p) and try writing p = 0; inside it. Read the compiler error. That is what const buys you: bugs caught at compile time.

Check your understanding

When should you pass const T& instead of by value?

When T is bigger than a register (structs, buffers), to avoid a copy. Pass int, float and pointers by value: faster and easier to read.

How does constexpr differ from const?

const means read-only, but the value may only be known at runtime. constexpr must be known at compile time, so it can size an array or be a template argument.

Interview angle

"Why not #define?" Answer: no type checking, it ignores namespaces and scope, the debugger cannot see the name, and macro expansion can cause side effects.

Module A · C++ for C programmers

namespace, overloading, enum class

20 min · Hardware: Board only

Goal Organize names, and understand why C++ needs name mangling

C

Function names must be unique, so you write log_int, log_float, and an enum mixes with int anywhere.

C++

One name can be overloaded for different parameters, namespace prevents name clashes, and enum class never converts to int by itself and can set its size with : uint8_t.

Hands-on

logx.ino
namespace logx {
void info(const char* msg) {
  Serial.print("[I] "); Serial.println(msg);
}
void info(const char* key, int value) {
  Serial.print("[I] "); Serial.print(key); Serial.print('='); Serial.println(value);
}
void info(const char* key, float value, int digits = 2) {   // default argument
  Serial.print("[I] "); Serial.print(key); Serial.print('='); Serial.println(value, digits);
}
}  // namespace logx

enum class Mode : uint8_t { Off, Slow, Fast };

void setup() {
  Serial.begin(115200);
  while (!Serial) {}
  logx::info("boot");
  logx::info("uptime_ms", (int)millis());
  logx::info("vbat", 3.71f);
  logx::info("pi", 3.14159f, 4);
  Mode m = Mode::Slow;
  logx::info("mode", static_cast<int>(m));   // explicit cast required
  // int bad = m;   // uncomment this line: compile error
}

void loop() {}

Check your understanding

How do you include a library written in C?

Wrap the header in extern "C" { … } so the linker finds the C-style symbol names. Without it you get undefined reference errors.

Why is enum class safer than enum?

It never converts to int implicitly, its enumerator names do not leak into the outer scope, and you can set the underlying type to control its size in memory.

Module A · C++ for C programmers

class: encapsulation and constructors

30 min · Hardware: LED + R 1 kΩ

Goal Write a Led class that hides the active-LOW detail inside

C

A struct holds the data and a separate function led_on(&led) acts on it. Anyone can change the fields.

C++

Data (private) and behavior (public) live together. The compiled code is about the same size, because this is just a hidden pointer argument.

Hands-on

led_class.ino
class Led {
public:
  Led(uint8_t pin, bool activeLow) : pin_(pin), activeLow_(activeLow) {}

  void begin() { pinMode(pin_, OUTPUT); off(); }
  void on()     { write(true); }
  void off()    { write(false); }
  void toggle() { write(!isOn_); }
  bool isOn() const { return isOn_; }   // const method: does not change state

private:
  void write(bool on) {
    isOn_ = on;
    digitalWrite(pin_, (on != activeLow_) ? HIGH : LOW);
  }
  uint8_t pin_;
  bool activeLow_;
  bool isOn_ = false;
};

Led red(LED_RED, true);   // on-board: active-LOW
Led ext(D2, false);       // external: active-HIGH

void setup() {
  red.begin();
  ext.begin();
}

void loop() {
  red.toggle();
  ext.toggle();
  delay(300);
}

Why a separate begin() instead of calling pinMode in the constructor? Global objects are constructed before main() and before init(), so the hardware may not be ready yet. This is a standard embedded C++ pattern.

Try it: move the class to src/Led.h (create a src folder inside the sketch folder and start the file with #pragma once and #include <Arduino.h>), then #include "src/Led.h". You will reuse it in lesson 11.

Check your understanding

Why is a member initializer list (: pin_(pin)) better than assigning in the body?

Members are constructed with the right value from the start instead of being default-constructed and then assigned. It is required for const and reference members.

Roughly how many bytes of RAM does a Led object use?

About 3–4 bytes (pin_, activeLow_, isOn_ + padding). Member functions cost no RAM per object; they live in flash and are shared.

Interview angle

"Static initialization order fiasco" is a mid-level question: the construction order of global objects across files is unspecified. The fixes are begin() or a function-local static.

Module A · C++ for C programmers

RAII and destructors

25 min · Hardware: 10 kΩ pot on A0

Goal Let scope manage resources automatically: timing, disabling/enabling interrupts

RAII (Resource Acquisition Is Initialization): acquire the resource in the constructor and release it in the destructor. The compiler always calls the destructor when the object leaves scope, so you can never forget unlock or enable_irq, even if you return early. C has no such mechanism.

Hands-on

Wire the potentiometer: outer legs to 3V3 and GND, middle leg to A0.

raii.ino
class ScopedTimer {
public:
  explicit ScopedTimer(const char* label) : label_(label), start_(micros()) {}
  ~ScopedTimer() {
    uint32_t us = micros() - start_;
    Serial.print(label_); Serial.print(": "); Serial.print(us); Serial.println(" us");
  }
  ScopedTimer(const ScopedTimer&) = delete;             // no copying
  ScopedTimer& operator=(const ScopedTimer&) = delete;
private:
  const char* label_;
  uint32_t start_;
};

// Nestable interrupt disable: save the previous state, then restore it
class CriticalSection {
public:
  CriticalSection() : primask_(__get_PRIMASK()) { __disable_irq(); }
  ~CriticalSection() { __set_PRIMASK(primask_); }
private:
  uint32_t primask_;
};

void setup() { Serial.begin(115200); }

void loop() {
  long sum = 0;
  {
    ScopedTimer t("analogRead x100");
    for (int i = 0; i < 100; ++i) sum += analogRead(A0);
  }                                   // destructor runs here
  Serial.print("avg = "); Serial.println(sum / 100);
  delay(1000);
}

Check your understanding

Why = delete the copy constructor?

If copying were allowed, two objects would run the destructor, e.g. re-enabling interrupts twice or printing the time twice. A resource with a single owner should not be copyable.

Can CriticalSection be used with BLE (SoftDevice)?

Only for a very short time, a few microseconds. If interrupts stay off longer, the SoftDevice misses radio timing. Real projects use sd_nvic_critical_region_enter instead.

Interview angle

If asked "what is the biggest advantage of C++ over C in embedded?", RAII is a strong answer: zero runtime overhead, and it removes a whole class of resource-leak bugs.

Module A · C++ for C programmers

Buttons, debounce and state machines

30 min · Hardware: Button on D1

Goal Write non-blocking debounce as a class that does not depend on Arduino (you will test it in lesson 15)

Wire the button between D1 and GND and use INPUT_PULLUP: released = HIGH, pressed = LOW. The contacts bounce several times within a few milliseconds, so without debounce one press counts as many.

Hands-on

Create src/Debouncer.h in the sketch folder.

src/Debouncer.h
#pragma once
#include <stdint.h>

// Pure logic: never calls the Arduino API, so it can be tested on a PC
class Debouncer {
public:
  enum class Event : uint8_t { None, Pressed, Released };

  explicit Debouncer(uint32_t stableMs = 20) : stableMs_(stableMs) {}

  // raw: true = pressed (already converted from active-LOW), nowMs: current time
  Event update(bool raw, uint32_t nowMs) {
    if (raw != lastRaw_) {  // still bouncing → restart the timer
      lastRaw_ = raw;
      changedAt_ = nowMs;
      return Event::None;
    }
    if (raw != stable_ && (nowMs - changedAt_) >= stableMs_) {
      stable_ = raw;
      return stable_ ? Event::Pressed : Event::Released;
    }
    return Event::None;
  }

  bool isPressed() const { return stable_; }

private:
  uint32_t stableMs_;
  uint32_t changedAt_ = 0;
  bool lastRaw_ = false;
  bool stable_ = false;
};
button_modes.ino
#include "src/Debouncer.h"

constexpr uint8_t kButtonPin = D1;
enum class Mode : uint8_t { Off, Slow, Fast };

Debouncer button;
Mode mode = Mode::Off;
uint32_t lastToggle = 0;
bool ledOn = false;

Mode next(Mode m) {
  switch (m) {
    case Mode::Off:  return Mode::Slow;
    case Mode::Slow: return Mode::Fast;
    case Mode::Fast: return Mode::Off;
  }
  return Mode::Off;
}

uint32_t periodMs(Mode m) { return m == Mode::Slow ? 500 : 100; }

void setup() {
  pinMode(kButtonPin, INPUT_PULLUP);
  pinMode(LED_GREEN, OUTPUT);
  digitalWrite(LED_GREEN, HIGH);
}

void loop() {
  uint32_t now = millis();
  bool pressed = (digitalRead(kButtonPin) == LOW);
  if (button.update(pressed, now) == Debouncer::Event::Pressed) {
    mode = next(mode);
  }
  if (mode == Mode::Off) {
    digitalWrite(LED_GREEN, HIGH);
  } else if (now - lastToggle >= periodMs(mode)) {
    lastToggle = now;
    ledOn = !ledOn;
    digitalWrite(LED_GREEN, ledOn ? LOW : HIGH);
  }
}

Check your understanding

Why is now - lastToggle still correct when millis() overflows (after about 49.7 days)?

Unsigned 32-bit subtraction is modulo 2³², so the difference is always right as long as the interval is under 49.7 days. Never write now > lastToggle + period; that breaks on overflow.

Why is there another return Mode::Off after the switch?

Some compilers warn "control reaches end of non-void function" even when every case is covered. It is there for safety and a warning-free build.

Module A · C++ for C programmers

Inheritance, virtual and interfaces

25 min · Hardware: Pot on A0

Goal Design an ISensor interface that lets you swap a real sensor for a fake one, and know what virtual costs

In C you build polymorphism yourself from a struct of function pointers. In C++ you write virtual and the compiler builds the table (vtable) for you. The main benefit in embedded is swapping implementations, for example using FakeSensor in tests without touching the calling code.

Hands-on

sensors.ino
class ISensor {
public:
  virtual ~ISensor() = default;
  virtual const char* name() const = 0;   // pure virtual = must override
  virtual float read() = 0;
};

class PotSensor : public ISensor {
public:
  explicit PotSensor(uint8_t pin) : pin_(pin) {}
  const char* name() const override { return "pot"; }
  float read() override { return analogRead(pin_) * (100.0f / 1023.0f); }  // %
private:
  uint8_t pin_;
};

class FakeSensor : public ISensor {
public:
  const char* name() const override { return "fake"; }
  float read() override { t_ += 0.1f; return 50.0f + 40.0f * sinf(t_); }
private:
  float t_ = 0;
};

PotSensor pot(A0);
FakeSensor fake;
ISensor* sensors[] = {&pot, &fake};

void setup() { Serial.begin(115200); }

void loop() {
  for (ISensor* s : sensors) {
    Serial.print(s->name()); Serial.print(':');
    Serial.print(s->read()); Serial.print(' ');
  }
  Serial.println();
  delay(50);
}

Open Tools → Serial Plotter to see two lines: the pot as you turn it, and a sine wave.

Check your understanding

Why does the base class need a virtual destructor?

If you delete an object through a base pointer and the destructor is not virtual, the derived destructor never runs and resources leak.

What can you use if you do not want to pay for virtual?

Templates (static polymorphism / CRTP): the compiler knows the type at compile time and can inline, at the cost of possibly larger code.

Interview angle

Classic question: "Is virtual slow?" Answer with numbers: two extra loads plus an indirect branch per call, a few cycles on a Cortex-M4. The real cost is that the call cannot be inlined, not raw speed.

Module A · C++ for C programmers

Template: RingBuffer<T, N>

30 min · Hardware: Pot on A0

Goal Write a reusable fixed-size container for any type, without the heap

C

Write separate buffers for int and float, or use void* + macros with no type safety.

C++

A template lets the compiler generate code for each type. N is a compile-time value you can check with static_assert.

Hands-on

Create src/RingBuffer.h.

src/RingBuffer.h
#pragma once
#include <stddef.h>

// Fixed-size FIFO, no heap: N is set at compile time
template <typename T, size_t N>
class RingBuffer {
  static_assert(N > 0, "N must be > 0");

public:
  bool push(const T& v) {
    if (count_ == N) return false;  // full
    buf_[head_] = v;
    head_ = (head_ + 1) % N;
    ++count_;
    return true;
  }

  bool pop(T& out) {
    if (count_ == 0) return false;  // empty
    out = buf_[tail_];
    tail_ = (tail_ + 1) % N;
    --count_;
    return true;
  }

  // when full, drop the oldest (good for a moving average)
  void pushOverwrite(const T& v) {
    if (count_ == N) {
      T dropped;
      pop(dropped);
    }
    push(v);
  }

  size_t size() const { return count_; }
  bool full() const { return count_ == N; }
  const T& at(size_t i) const { return buf_[(tail_ + i) % N]; }  // 0 = oldest

private:
  T buf_[N]{};
  size_t head_ = 0, tail_ = 0, count_ = 0;
};

template <typename T, size_t N>
float average(const RingBuffer<T, N>& rb) {
  if (rb.size() == 0) return 0.0f;
  float sum = 0;
  for (size_t i = 0; i < rb.size(); ++i) sum += rb.at(i);
  return sum / rb.size();
}
moving_average.ino
#include "src/RingBuffer.h"

RingBuffer<uint16_t, 16> samples;   // last 16 values

void setup() { Serial.begin(115200); }

void loop() {
  uint16_t raw = analogRead(A0);
  samples.pushOverwrite(raw);
  Serial.print("raw:"); Serial.print(raw);
  Serial.print(" avg:"); Serial.println(average(samples));
  delay(20);
}

Open Serial Plotter and compare the raw and avg lines. Try N = 4 and N = 64 and watch the lag and smoothness (an N-point moving average delays the signal by about N/2 samples).

Check your understanding

What happens to flash if you use RingBuffer<uint16_t,16> and RingBuffer<float,16>?

The compiler generates two copies of the code (template instantiation), so flash grows. Too many types leads to code bloat.

Is it safe if an ISR pushes and loop pops?

Not yet, because count_ is changed from both sides. Wrap it in a CriticalSection, or design an SPSC buffer where the producer only touches head and the consumer only touches tail.

Module A · C++ for C programmers

Memory in embedded systems

25 min · Hardware: Board only

Goal Know where each kind of variable lives, and the rules real firmware teams follow

Hands-on

memmap.ino
uint8_t bigStatic[8192];        // .bss  → counted in "Global variables use"
const char kMsg[] = "hello";    // .rodata → lives in flash

void setup() {
  Serial.begin(115200);
  while (!Serial) {}
  uint8_t onStack[256];         // stack → not in the compile-time numbers
  onStack[0] = 1;
  bigStatic[0] = onStack[0];
  Serial.print("flash  : 0x"); Serial.println((uintptr_t)kMsg, HEX);
  Serial.print("static : 0x"); Serial.println((uintptr_t)bigStatic, HEX);
  Serial.print("stack  : 0x"); Serial.println((uintptr_t)onStack, HEX);
}

void loop() {}

Check that the addresses start with 0x000… (flash) or 0x2000… (RAM) as in the diagram. Then change bigStatic to 32768 and watch the RAM figure change at compile time.

Rules real teams use

  • Allocate memory at init only. Never new/malloc in the loop afterwards: the heap fragments and the device fails after days of running.
  • Avoid Arduino's String; use char buf[32] + snprintf instead.
  • Use std::array / fixed-size buffers, and avoid std::vector and std::function, which may allocate on the heap.
  • Embedded builds often disable exceptions and RTTI (-fno-exceptions -fno-rtti), so errors are handled with return values.

Check your understanding

Where does a static variable inside a function live?

In .data or .bss like a global, but its scope is limited to the function, so it keeps its value between calls.

What does a stack overflow look like on an MCU without an OS?

The stack grows down into the heap or .bss, causing random variable corruption or a HardFault. Detect it with stack painting (fill a pattern and see how deep it gets overwritten) or an MPU guard region.

Interview angle

Be ready to explain .text / .data / .bss / heap / stack with this diagram in under a minute. It comes up almost everywhere.

Module A · C++ for C programmers

Interrupts, volatile and lambdas

25 min · Hardware: Button on D1

Goal Write a correct ISR, and share data between the ISR and loop safely

Hands-on

isr_count.ino
constexpr uint8_t kButtonPin = D1;
volatile uint32_t pressCount = 0;   // volatile: changes outside normal flow, never cache

void setup() {
  Serial.begin(115200);
  pinMode(kButtonPin, INPUT_PULLUP);
  // a capture-less lambda converts to a function pointer
  attachInterrupt(digitalPinToInterrupt(kButtonPin), [] {
    pressCount = pressCount + 1;
  }, FALLING);
}

void loop() {
  uint32_t count;
  noInterrupts();          // copy it out atomically
  count = pressCount;
  interrupts();
  Serial.println(count);
  delay(500);
}

Press the button once and the number often goes up by more than 1. That is the bounce from lesson 6. Conclusion: an ISR on a mechanical button still needs time-based debounce (e.g. check millis() in the ISR, or send an event for loop to handle).

Check your understanding

Does volatile make pressCount++ atomic?

No. volatile only forces a real memory read/write every time, but ++ is load-add-store, three instructions that can be interrupted. Use a critical section or std::atomic.

What must you never do in an ISR?

delay(), Serial.print(), malloc/new, long work, or calling non-reentrant functions. Let the ISR set a flag or push into a buffer, and return as fast as possible.

Interview angle

volatile is the most common embedded interview question. Cover all three cases: variables changed by an ISR, memory-mapped registers, and variables shared between threads, and say that it is not synchronization.

Module A · C++ for C programmers

Mini project: cooperative scheduler

30 min · Hardware: LED + button + pot

Goal Combine everything into firmware with no delay() at all. Real products use this structure before moving to an RTOS

Hands-on

Name the folder firmware/ and the file firmware.ino (Arduino requires matching names). src/ holds Led.h, Debouncer.h and RingBuffer.h from earlier lessons.

firmware/firmware.ino
#include "src/Led.h"
#include "src/Debouncer.h"
#include "src/RingBuffer.h"

#if __has_include("src/version.h")
#include "src/version.h"          // generated by CI (lesson 17)
#else
#define FW_VERSION "dev"
#endif

constexpr uint8_t kButtonPin = D1;
constexpr uint8_t kPotPin    = A0;

Led status(LED_GREEN, true);
Led ext(D2, false);
Debouncer button;
RingBuffer<uint16_t, 16> samples;
bool paused = false;

struct Task {
  uint32_t periodMs;
  uint32_t lastRunMs;
  void (*run)();
};

void blinkTask() { if (!paused) status.toggle(); }

void buttonTask() {
  bool pressed = digitalRead(kButtonPin) == LOW;
  if (button.update(pressed, millis()) == Debouncer::Event::Pressed) {
    paused = !paused;
    ext.toggle();
  }
}

void sensorTask() { samples.pushOverwrite(analogRead(kPotPin)); }

void reportTask() {
  Serial.print("avg:");     Serial.print(average(samples));
  Serial.print(" paused:"); Serial.println(paused ? 1 : 0);
}

Task tasks[] = {
  {500, 0, blinkTask},
  {5,   0, buttonTask},
  {20,  0, sensorTask},
  {200, 0, reportTask},
};

// type 50–5000 and press Enter to change the blink period
void handleSerial() {
  static char buf[16];
  static size_t len = 0;
  while (Serial.available()) {
    char c = Serial.read();
    if (c == '\n' || c == '\r') {
      if (len > 0) {
        buf[len] = '\0';
        long ms = atol(buf);
        if (ms >= 50 && ms <= 5000) tasks[0].periodMs = ms;
        len = 0;
      }
    } else if (len < sizeof(buf) - 1) {
      buf[len++] = c;
    }
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(kButtonPin, INPUT_PULLUP);
  status.begin();
  ext.begin();
  Serial.print("fw "); Serial.println(FW_VERSION);
}

void loop() {
  uint32_t now = millis();
  for (Task& t : tasks) {
    if (now - t.lastRunMs >= t.periodMs) {
      t.lastRunMs = now;
      t.run();
    }
  }
  handleSerial();
}

Test it: press the button → the green LED stops and the external LED turns on; turn the pot and watch avg in the Plotter; type 100 in Serial Monitor → faster blinking. Everything runs at once with no delay().

Check your understanding

If reportTask takes 30 ms, what happens to buttonTask?

buttonTask waits until reportTask finishes, because scheduling is cooperative (no preemption). Every task must be short; when that is no longer possible, it is time for an RTOS.

Why does Task use a function pointer instead of std::function?

A function pointer is 4 bytes, never allocates and is predictable. std::function may allocate on the heap when it captures data.

Module C · Testable code and CI/CD

Separate logic from hardware + unit tests on a PC

30 min · Hardware: Computer

Goal Run the Debouncer and RingBuffer tests on a PC in seconds, with no board plugged in

The Debouncer takes the time as a parameter (nowMs) instead of calling millis() itself. This is the simplest form of dependency injection, and it lets a test control time down to the millisecond.

Hands-on

test/test_main.cpp
#include <cstdio>
#include <cstdlib>
#include "RingBuffer.h"
#include "Debouncer.h"

static int failures = 0;
#define CHECK(cond)                                                    \
  do {                                                                 \
    if (!(cond)) {                                                     \
      std::printf("FAIL %s:%d  %s\n", __FILE__, __LINE__, #cond);      \
      ++failures;                                                      \
    }                                                                  \
  } while (0)

static void test_ringbuffer() {
  RingBuffer<int, 3> rb;
  CHECK(rb.size() == 0);
  CHECK(rb.push(1) && rb.push(2) && rb.push(3));
  CHECK(!rb.push(4));          // already full
  int v = 0;
  CHECK(rb.pop(v) && v == 1);  // FIFO: first in, first out
  rb.pushOverwrite(4);
  rb.pushOverwrite(5);         // full → drops 2
  CHECK(rb.at(0) == 3 && rb.at(2) == 5);
  CHECK(average(rb) == 4.0f);
}

static void test_debouncer() {
  using E = Debouncer::Event;
  Debouncer d(20);
  CHECK(d.update(true, 0) == E::None);   // press starts
  CHECK(d.update(false, 5) == E::None);  // bounce
  CHECK(d.update(true, 8) == E::None);   // bounce
  CHECK(d.update(true, 20) == E::None);  // stable for only 12 ms
  CHECK(d.update(true, 28) == E::Pressed);
  CHECK(d.isPressed());
  CHECK(d.update(true, 40) == E::None);  // held down, no repeat event
}

int main() {
  test_ringbuffer();
  test_debouncer();
  if (failures == 0) std::puts("ALL TESTS PASSED");
  return failures == 0 ? EXIT_SUCCESS : EXIT_FAILURE;
}
terminal
# Linux / macOS / WSL (Windows: install g++ via MSYS2, or use WSL)
g++ -std=c++17 -Wall -Wextra -Werror -Ifirmware/src test/test_main.cpp -o test_runner
./test_runner
# ALL TESTS PASSED

Make a test fail on purpose: change >= stableMs_ in Debouncer.h to >, run again and see which line FAILs. Then change it back and commit with test: add host unit tests.

Real projects use a framework such as GoogleTest, Catch2 or Unity (for C), but the idea is the same: CHECK a condition, report the failing line, and exit with a non-zero code on failure so CI knows.

Check your understanding

Why does the exit code matter?

CI decides pass/fail from each command's exit code: 0 = pass, anything else = fail, which stops the pipeline.

How do you test code that calls digitalRead()?

Hide hardware access behind an interface (like ISensor in lesson 7) and plug in a fake/mock for tests, or pass the value in instead of letting the function read it.

Interview angle

"How do you test firmware?" Answer in layers: host unit tests for logic, HIL tests on real boards for drivers, system tests for features, and say that the first layer runs in CI on every commit.

Hands-on

.github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:

env:
  BOARD_URL: https://files.seeedstudio.com/arduino/package_seeeduino_boards_index.json

      - uses: actions/checkout@v4

      - name: Run tests
        run: ./test_runner
      - name: Static analysis

  build-firmware:
    needs: host-tests
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      - run: pip install adafruit-nrfutil   # the core needs it to package the .zip on Linux
      - uses: arduino/setup-arduino-cli@v2
      - name: Install board core
        run: |
          arduino-cli core update-index --additional-urls "$BOARD_URL"
          arduino-cli core install Seeeduino:nrf52 --additional-urls "$BOARD_URL"
      - name: Compile
        run: arduino-cli compile --fqbn "$FQBN" --additional-urls "$BOARD_URL" --output-dir out firmware
      - uses: actions/upload-artifact@v4
        with:
          name: firmware
          path: out/

Check your understanding

What is needs: host-tests for?

build-firmware runs only after the tests pass, which saves time and makes the order of priority clear. Without it, the two jobs run in parallel.

Why pin the core and action versions?

For reproducible builds. If the core updates itself, the firmware may change behavior without anyone touching the code. It is the same idea as a locked BOM in hardware.

Interview angle

Be clear about CI vs CD: CI = integrate code often and check it automatically every time; CD = deliver ready-to-use artifacts automatically (next lesson).

CD: automatic firmware releases from tags

25 min · Hardware: Board + computer

Goal Push a tag and get a GitHub Release with the firmware files and the version number built in

Hands-on

.github/workflows/release.yml
name: Release

on:
  push:
    tags: ['v*.*.*']

permissions:
  contents: write

env:
  BOARD_URL: https://files.seeedstudio.com/arduino/package_seeeduino_boards_index.json
  FQBN: Seeeduino:nrf52:xiaonRF52840Sense

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      - run: pip install adafruit-nrfutil
      - uses: arduino/setup-arduino-cli@v2
      - run: |
          arduino-cli core update-index --additional-urls "$BOARD_URL"
          arduino-cli core install Seeeduino:nrf52 --additional-urls "$BOARD_URL"
      - name: Stamp version
        run: echo "#define FW_VERSION \"${GITHUB_REF_NAME}\"" > firmware/src/version.h
      - name: Compile
        run: arduino-cli compile --fqbn "$FQBN" --additional-urls "$BOARD_URL" --output-dir out firmware
      - uses: softprops/action-gh-release@v2
        with:
          files: |
            out/*.hex
            out/*.zip
          generate_release_notes: true
terminal
git add .github/workflows/release.yml
git commit -m "ci: release firmware on version tag"
git push

git tag -a v0.1.0 -m "first release: scheduler, debounce, moving average"
git push origin v0.1.0

Open the Releases page, download the .hex and flash it. Serial Monitor must show fw v0.1.0 (a local build shows fw dev). This is traceability: you always know which firmware commit each board runs.

SemVer: MAJOR.MINOR.PATCH. Bug fix → +PATCH, backward-compatible feature → +MINOR, breaking change (e.g. a protocol) → +MAJOR. If you want a .uf2 to drag and drop after a double-tap reset, convert the .hex with uf2conv.py (family 0xADA52840).

Check your understanding

Why generate version.h in CI instead of writing the version in the code?

The tag becomes the single source of truth, so you cannot forget to bump the number, and local builds say "dev", clearly not a release.

Is permissions: contents: write required?

Yes. In many repos the default GITHUB_TOKEN is read-only, and creating a Release needs write access.

Questions you should answer in under a minute

How does C++ differ from C in embedded work, and what does it cost?

You get classes, RAII, references, templates, constexpr, enum class and namespaces, mostly with no runtime cost. The costly parts are virtual (vtables), exceptions, RTTI and heap use through some STL types, so teams use a subset.

When do you use volatile, and what does it not do?

For variables changed by an ISR, peripheral registers and data shared between contexts. It does not make anything atomic and it is not a memory barrier.

What makes a good ISR?

Short, non-blocking, no allocation. It sets a flag or pushes into a ring buffer and leaves the processing to main or a task. Shared data must be protected with a critical section.

Why avoid dynamic allocation after init?

Fragmentation, unpredictable timing, and failures after long run times. Systems that must run continuously allocate everything statically.

Explain RAII with an example

Tie a resource's lifetime to an object: CriticalSection disables interrupts in its ctor and restores them in its dtor, however you leave the scope.

What are the ways to debounce?

Hardware (RC + Schmitt trigger) and software (wait until stable for a set time, or sample several times). Choose based on BOM cost versus CPU time.

How do you choose between merge and rebase?

merge keeps the real history and is safe on shared branches. rebase gives a straight-line history; use it on private branches before opening a PR.

What should a firmware CI/CD pipeline include?

Builds for every target, host unit tests, static analysis, stored artifacts, and tag-based releases with the version built into the binary. The next step is HIL tests on a runner wired to real boards.

Interview angle

Your existing PCB, failure analysis and V&V experience is a strength that pure firmware people do not have. Connect both sides in your portfolio, e.g. explain how you chose the LED resistor and the debounce time.
