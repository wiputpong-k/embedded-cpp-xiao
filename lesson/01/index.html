.ino คือ C++ และเส้นทางจากโค้ดถึงบอร์ด

25 นาที · ฮาร์ดแวร์: บอร์ดอย่างเดียว

ในบทนี้
  1. Hands-on
  2. เช็กความเข้าใจ

เป้าหมาย เข้าใจว่า Arduino ซ่อนอะไรไว้ และเห็น toolchain จริง

ถ้าเคยเขียน C บน microcontroller (MCU: ชิปตัวเดียวที่มี CPU, หน่วยความจำ และขา I/O อยู่ในตัว เช่น nRF52840 บน XIAO) คุณเขียน main() เองใน src/main.c แล้วใครเรียก main()? บน PC คือ OS แต่ MCU ไม่มี OS: เมื่อจ่ายไฟหรือกด reset CPU จะรัน startup code (โค้ดสั้น ๆ ที่มากับชิป เช่นไฟล์ startup_xxx.s) ซึ่งเตรียม stack และตัวแปร global แล้วกระโดดไป main()

Arduino ใช้กลไกเดียวกัน ต่างแค่ main() ย้ายไปอยู่ใน core และ main() ตัวนั้นเรียก setup() กับ loop() ที่คุณเขียนใน .ino แทน sketch จึงไม่มี main()

".ino คือ C++" หมายความว่า .ino ไม่ใช่ภาษาพิเศษ IDE แค่เติม #include <Arduino.h> และสร้าง function prototype ให้ แล้วส่งให้ arm-none-eabi-g++ คอมไพล์เป็น C++ ปกติ ผลคือทุกอย่างของ C++ (class, namespace, template ฯลฯ) ใช้ใน sketch ได้ ซึ่งคือสิ่งที่คอร์สนี้สอนต่อไป และแยกโค้ดเป็นไฟล์ .h/.cpp ได้เหมือนโปรเจกต์ C++ ทั่วไป คำศัพท์ในย่อหน้านี้:

  • toolchain ชุดโปรแกรมที่แปลงโค้ดเป็นไฟล์ที่ลงชิปได้ (compiler, linker, เครื่องมือแปลงไฟล์) IDE เรียกให้เองเมื่อกด Verify
  • arm-none-eabi-g++ g++ แบบ cross-compiler คือรันบน PC แต่สร้างโค้ดให้ CPU อื่น: arm = CPU ตระกูล ARM (nRF52840 ใช้ Cortex-M4F), none = ไม่มี OS, eabi = มาตรฐานการเรียกฟังก์ชันและจัดข้อมูลของ ARM สำหรับ embedded
  • core โค้ดที่ผู้ผลิตเตรียมไว้ให้ชิปรุ่นนั้น มี main(), digitalWrite(), Serial ฯลฯ คือสิ่งที่ติดตั้งจาก Boards Manager ในบท 00
  • function prototype บรรทัดประกาศฟังก์ชันล่วงหน้า เช่น void blink(int ms); C++ บังคับให้ประกาศก่อนเรียก ใน .ino เขียนฟังก์ชันไว้ท้ายไฟล์ได้เพราะ IDE สร้างบรรทัดนี้ให้

main() ตัวจริงอยู่ใน core:

core/main.cpp (ย่อ)
int main() {
  init();          // clock, timer, USB CDC
  setup();
  for (;;) {
    loop();
  }
}

main() ของ core เรียก init() เตรียมฮาร์ดแวร์ เรียก setup() ครั้งเดียว แล้ววนเรียก loop() ไม่รู้จบ เพราะ firmware ไม่มี OS ให้ "จบแล้วกลับไป" สิ่งที่ init() เตรียม:

  • clock สัญญาณจังหวะที่ขับ CPU และวงจรอื่น (nRF52840 = 64 MHz) ต้องตั้งก่อนทุกอย่าง
  • timer วงจรนับเวลาในชิป เป็นที่มาของ millis() และ delay()
  • USB CDC ทำให้บอร์ดแสดงตัวเป็น serial port เสมือนผ่านสาย USB (พอร์ต COM ที่เห็นใน Windows) Serial Monitor คุยกับบอร์ดผ่านช่องนี้

core nRF52 ตัวจริงรัน setup()/loop() ใน task ของ FreeRTOS (OS ขนาดเล็กสำหรับ MCU) และมีขั้นตอนมากกว่านี้ แต่ลำดับ init → setup → loop เหมือนเดิม

ไฟล์และเครื่องมือในรูป:

  • .o (object file) ผลการ compile ทีละไฟล์ เป็นคำสั่งเครื่องของ ARM แล้ว แต่ยังไม่มี address จริง และยังเรียกฟังก์ชันในไฟล์อื่นไม่ได้
  • linker รวม .o ทุกไฟล์กับ core.a (core ที่ compile ไว้แล้ว) และ library แล้วต่อการเรียกข้ามไฟล์ให้ครบ
  • linker script ไฟล์บอก linker ว่า flash และ RAM เริ่มที่ address ไหน มีขนาดเท่าไร และโค้ดกับตัวแปรวางตรงไหน
  • .elf ผลของ linker มีทั้งโค้ดและ debug symbol (ชื่อฟังก์ชัน ตัวแปร เลขบรรทัด)
  • objcopy ตัดเหลือเฉพาะ byte ที่จะเขียนลงชิป (.hex, .uf2) จากนั้นขั้น upload หรือ flash ส่งไฟล์ให้ bootloader (โปรแกรมเล็ก ๆ ในชิปที่รับ firmware ใหม่) เขียนลงหน่วยความจำ

Hands-on

  1. เปิด Arduino IDE เลือกบอร์ดและพอร์ตเหมือนบท 00 แล้วสร้าง sketch ใหม่ (File → New Sketch) วางโค้ดด้านล่างแทนของเดิม บันทึกชื่อ whoami
  2. กด Upload รอจนแถบ Output ขึ้น Device programmed หรือ upload เสร็จ
  3. เปิด Tools → Serial Monitor แล้วตั้งความเร็วมุมขวาเป็น 115200 baud ถ้าไม่มีข้อความขึ้น ให้กด reset บนบอร์ด 1 ครั้ง
whoami.ino
#include <Adafruit_TinyUSB.h>   // เปิด USB และ Serial (core นี้ต้องมี)
void setup() {
  Serial.begin(115200);
  while (!Serial) {}             // รอ USB CDC พร้อม
  Serial.print("__cplusplus = ");  Serial.println(__cplusplus);
  Serial.print("sizeof(int) = ");  Serial.println(sizeof(int));
  Serial.print("sizeof(void*) = ");Serial.println(sizeof(void*));
  Serial.print("sizeof(bool) = "); Serial.println(sizeof(bool));
}

void loop() {}
  • Serial.begin(115200) เปิด serial ที่ 115200 baud (bit ต่อวินาที) สำหรับ USB CDC ตัวเลขนี้ไม่มีผลจริง แต่ให้ตั้งตรงกับ Serial Monitor จนเป็นนิสัย เพราะ serial แบบสายจริง (UART) ต้องตรงกันทั้งสองฝั่ง
  • while (!Serial) {} รอจนคอมพิวเตอร์เปิดพอร์ต ไม่อย่างนั้นข้อความจะถูกส่งออกไปก่อนเปิด Serial Monitor และหายไป
  • sizeof(x) ขนาดของชนิดข้อมูลเป็น byte

ผลที่ควรเห็น:

Serial Monitor
__cplusplus = 201103
sizeof(int) = 4
sizeof(void*) = 4
sizeof(bool) = 1

ค่า __cplusplus บอกมาตรฐานภาษาที่ compiler ใช้ (201103 = C++11, 201703 = C++17) จดไว้ เพราะ feature ที่ใช้ได้ขึ้นกับค่านี้ int และ pointer ได้ 4 byte เพราะ Cortex-M4F เป็น CPU 32-bit แต่บน Arduino Uno (8-bit) int มีแค่ 2 byte โค้ด embedded จึงไม่ควรเดาขนาด int

สุดท้ายดูบรรทัดท้ายของแถบ Output หลัง Verify หรือ Upload:

  • Sketch uses … bytes = ขนาดโปรแกรมใน flash หน่วยความจำถาวรที่เก็บโปรแกรม ไฟดับไม่หาย (nRF52840 มี 1 MB แต่ส่วนหนึ่งถูกจองให้ bootloader และ stack BLE จึงเห็น Maximum น้อยกว่านั้น)
  • Global variables use … = RAM แบบ static หน่วยความจำทำงาน (256 KB) ที่ไฟดับแล้วหาย "static" คือส่วนที่รู้ขนาดตั้งแต่ตอน build ได้แก่ตัวแปร global ส่วน RAM ที่เหลือใช้เป็น stack (ตัวแปร local) และ heap

เช็กความเข้าใจ

ถ้า __cplusplus ได้ 201103 จะใช้ if constexpr ได้ไหม?

ไม่ได้ if constexpr เป็นของ C++17 ต้องเพิ่ม flag -std=gnu++17 หรือเลี่ยงไปใช้ template overload

"Global variables use" นับ stack ด้วยไหม?

ไม่นับ นับเฉพาะ .data (global ที่มีค่าเริ่มต้น) + .bss (global ที่เริ่มเป็น 0) ซึ่งรู้ขนาดตอน link ตัวแปร local บน stack ไม่อยู่ในตัวเลขนี้

มุมงานจริง

ในงานจริงเมื่อ build มีปัญหา ให้ไล่ตามลำดับ preprocess → compile → link (linker script กำหนด address) → objcopy → flash จะรู้ว่าพังที่ขั้นไหน และเก็บ .elf ไว้เสมอ เพราะมี debug symbol ที่ debugger ต้องใช้ ส่วน .hex/.bin คือ image ที่ลงชิป
