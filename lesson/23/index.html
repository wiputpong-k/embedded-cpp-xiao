CD: release firmware อัตโนมัติด้วย tag

30 นาที · ฮาร์ดแวร์: บอร์ด + คอมพิวเตอร์

ในบทนี้
  1. ขั้นที่ 1: เพิ่ม workflow release
  2. ขั้นที่ 2: ติด tag แล้ว push
  3. ขั้นที่ 3: แฟลชไฟล์จาก Release ลงบอร์ด
  4. เช็กความเข้าใจ

เป้าหมาย push tag แล้วได้ GitHub Release ที่มีไฟล์ firmware และเลขเวอร์ชันฝังในตัว แล้วแฟลชไฟล์นั้นลงบอร์ดได้

CD (Continuous Delivery) คือการส่งมอบไฟล์ที่พร้อมใช้งานโดยอัตโนมัติ workflow ในบทนี้ทำงานเมื่อ push tag ที่ขึ้นต้นด้วย v เช่น v0.1.0 มันจะสร้างไฟล์ version.h จากชื่อ tag, compile firmware แล้วสร้างหน้า GitHub Release พร้อมแนบไฟล์ให้ดาวน์โหลด

ขั้นที่ 1: เพิ่ม workflow release

main ถูกตั้งกฎให้รับการเปลี่ยนแปลงผ่าน PR เท่านั้น (บท 18) จึงต้องเพิ่มไฟล์นี้ผ่าน PR เหมือนเดิม สร้างไฟล์ .github/workflows/release.yml ด้วยเนื้อหาข้างล่าง แล้วรันคำสั่งชุดถัดไป

.github/workflows/release.yml
name: Release

on:
  push:
    tags: ['v*.*.*']

permissions:
  contents: write

env:
  BOARD_URL: https://files.seeedstudio.com/arduino/package_seeeduino_boards_index.json
  FQBN: Seeeduino:nrf52:xiaonRF52840Sense

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      - run: pip install adafruit-nrfutil
      - uses: arduino/setup-arduino-cli@v2
      - run: |
          arduino-cli core update-index --additional-urls "$BOARD_URL"
          arduino-cli core install Seeeduino:nrf52 --additional-urls "$BOARD_URL"
      - name: Stamp version
        run: echo "#define FW_VERSION \"${GITHUB_REF_NAME}\"" > firmware/src/version.h
      - name: Compile
        run: arduino-cli compile --fqbn "$FQBN" --additional-urls "$BOARD_URL" --output-dir out firmware
      - uses: softprops/action-gh-release@v2
        with:
          files: |
            out/*.hex
            out/*.zip
          generate_release_notes: true
Git Bash
git switch -c ci/release
git add .github/workflows/release.yml
git commit -m "ci: release firmware on version tag"
git push -u origin ci/release
gh pr create --fill
gh pr checks --watch
gh pr merge --squash --delete-branch
git switch main
git pull

ขั้นที่ 2: ติด tag แล้ว push

tag คือป้ายชื่อที่ติดไว้กับ commit หนึ่ง ใช้บอกว่า commit นี้คือเวอร์ชันอะไร การ push tag ไม่ต้องผ่าน PR หลัง push ให้เปิดแท็บ Actions ดู workflow Release ทำงาน เมื่อเสร็จจะมีหน้า Release ใหม่ (gh release view --web)

Git Bash
git tag -a v0.1.0 -m "first release: scheduler, debounce, moving average"
git push origin v0.1.0
gh release view --web

ขั้นที่ 3: แฟลชไฟล์จาก Release ลงบอร์ด

บอร์ด XIAO nRF52840 รับ firmware ผ่าน bootloader ด้วยไฟล์ .zip (DFU package) ไม่ใช่ไฟล์ .hex โดยตรง Arduino IDE ทำขั้นนี้ให้ทุกครั้งที่กด Upload ส่วนไฟล์จาก Release ต้องใช้เครื่องมือ adafruit-nrfutil

  1. ถ้ายังไม่มี Python ให้ติดตั้งก่อน (คำสั่งแรกข้างล่าง ใน PowerShell) แล้วปิด terminal เปิดใหม่ จากนั้นติดตั้ง adafruit-nrfutil ด้วย pip
  2. ใน Git Bash ดาวน์โหลดไฟล์ .zip จาก Release (ชื่อประมาณ firmware.ino.zip)
  3. กดปุ่ม reset บนบอร์ด 2 ครั้งเร็ว ๆ ให้เข้า bootloader แล้วดูเลขพอร์ตใน Arduino IDE ที่ Tools → Port (เช่น COM5)
  4. รันคำสั่ง adafruit-nrfutil โดยเปลี่ยน COM5 เป็นพอร์ตของคุณ รอจนขึ้นว่า Device programmed
  5. เปิด Serial Monitor (115200 baud) แล้วกด reset 1 ครั้ง ต้องเห็น fw v0.1.0 (ถ้า build จาก IDE ในเครื่องจะเห็น fw dev)
PowerShell
winget install -e --id Python.Python.3.12
pip install adafruit-nrfutil
Git Bash
gh release download v0.1.0 --pattern "*.zip"
adafruit-nrfutil --verbose dfu serial --package firmware.ino.zip -p COM5 -b 115200 --singlebank

นี่คือ traceability: รู้เสมอว่าบอร์ดตัวไหนรัน firmware เวอร์ชันไหน และย้อนไปดูโค้ดของเวอร์ชันนั้นได้จาก tag

SemVer: MAJOR.MINOR.PATCH แก้บั๊ก +PATCH, ฟีเจอร์ใหม่ที่เข้ากันได้ +MINOR, เปลี่ยนแบบเข้ากันไม่ได้ (เช่น protocol) +MAJOR ถ้าต้องการไฟล์ .uf2 สำหรับลากวางลงไดรฟ์ที่ขึ้นมาตอน double-tap reset ให้แปลงจาก .hex ด้วย uf2conv.py (family 0xADA52840)

เช็กความเข้าใจ

ทำไมสร้าง version.h ใน CI แทนเขียนเลขเวอร์ชันในโค้ด?

ให้ tag เป็นแหล่งความจริงแหล่งเดียว ลืมแก้เลขไม่ได้ และ build ในเครื่องจะติด "dev" ชัดเจนว่าไม่ใช่ของ release

permissions: contents: write จำเป็นไหม?

จำเป็น GITHUB_TOKEN ค่าเริ่มต้นอ่านอย่างเดียวในหลาย repo ต้องให้สิทธิ์เขียนเพื่อสร้าง Release
