CI 1: รัน test อัตโนมัติด้วย GitHub Actions

30 นาที · ฮาร์ดแวร์: คอมพิวเตอร์

ในบทนี้
  1. Hands-on
  2. ลองทำให้ CI แดง
  3. เช็กความเข้าใจ

เป้าหมาย ทุก push และทุก PR ถูก test อัตโนมัติบนเซิร์ฟเวอร์ของ GitHub

CI (Continuous Integration) คือการให้เครื่องตรวจโค้ดทุกครั้งที่มีการเปลี่ยนแปลง GitHub Actions อ่านไฟล์ workflow (เขียนด้วย YAML) ในโฟลเดอร์ .github/workflows/ แล้วเปิดเครื่อง Linux ชั่วคราว (runner) มารันคำสั่งตามนั้น บทนี้เริ่มจาก job เดียวคือ host-tests ที่รัน test จากบท 19–20 บทหน้าจะเพิ่ม job compile firmware

Hands-on

  1. ใน Git Bash เข้าไปที่ repo สร้าง branch ใหม่ และสร้างโฟลเดอร์ .github/workflows (3 บรรทัดแรกของชุดคำสั่งข้างล่าง)
  2. รัน notepad .github/workflows/ci.yml วางเนื้อหา ci.yml ข้างล่าง แล้วบันทึก YAML นับการเว้นวรรคเป็นโครงสร้าง ต้องใช้ space ห้ามใช้ Tab และระยะย่อหน้าต้องตรงตามตัวอย่าง
  3. commit, push แล้วเปิด PR จากนั้นรัน gh pr checks --watch เพื่อดูสถานะ job แบบ live
  4. เปิดหน้า PR บนเว็บ แท็บ Checks หรือแท็บ Actions ของ repo คลิกที่ job host-tests แล้วคลิกแต่ละ step เพื่อดู log
  5. เมื่อเป็นสีเขียวแล้ว merge PR นี้ (gh pr merge --squash --delete-branch)
Git Bash
cd ~/xiao-embedded-cpp
git switch -c ci/host-tests
mkdir -p .github/workflows
# วาง ci.yml แล้วบันทึก จากนั้น:
git add .github/
git commit -m "ci: run host tests on every push and PR"
git push -u origin ci/host-tests
gh pr create --fill
gh pr checks --watch        # ดูสถานะ job แบบ live
.github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:

jobs:
  host-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build tests
        run: g++ -std=c++17 -Wall -Wextra -Werror -Ifirmware/src test/test_main.cpp -o test_runner
      - name: Run tests
        run: ./test_runner
      - name: Static analysis
        run: |
          sudo apt-get update && sudo apt-get install -y cppcheck
          cppcheck --error-exitcode=1 --enable=warning,performance --std=c++17 -Ifirmware/src test/test_main.cpp

ลองทำให้ CI แดง

สร้าง branch ใหม่ แก้ >= ใน Debouncer.h เป็น > แบบบท 20 แล้ว push และเปิด PR หน้า PR จะขึ้นกากบาทสีแดง คลิกดู log ของ step Run tests จะเห็นบรรทัด FAIL เดียวกับที่เห็นในเครื่อง จากนั้นปิด PR นี้ทิ้งด้วย gh pr close --delete-branch

เช็กความเข้าใจ

runner ของ GitHub เป็น Linux แต่เครื่องเราเป็น Windows ทำไม test ยังได้ผลเหมือนกัน?

เพราะโค้ดที่ test เป็น C++ มาตรฐานล้วน ไม่ขึ้นกับระบบปฏิบัติการหรือฮาร์ดแวร์ นี่คืออีกประโยชน์ของการแยก logic ออกจากฮาร์ดแวร์ในบท 19

ทำไม job ถึงขึ้นสีแดงเมื่อ test fail?

./test_runner คืน exit code 1 เมื่อมี CHECK ไม่ผ่าน GitHub Actions ถือว่า step ที่คืนค่าไม่เป็น 0 คือ fail และหยุด job ทันที
