Branch, merge และแก้ conflict

25 นาที · ฮาร์ดแวร์: คอมพิวเตอร์

ในบทนี้
  1. Hands-on: สร้าง conflict เองแล้วแก้
  2. เช็กความเข้าใจ

เป้าหมาย แยกงานเป็น branch และแก้ merge conflict ได้โดยไม่ตื่นตระหนก

  • branch เส้นทางงานแยกออกมาจาก main commit บน branch ไม่กระทบ main จนกว่าจะรวมกลับ
  • merge การรวมงานจาก branch หนึ่งเข้าอีก branch ถ้าแก้คนละบรรทัด Git รวมให้เองอัตโนมัติ
  • conflict เมื่อทั้งสอง branch แก้บรรทัดเดียวกัน Git ไม่รู้ว่าจะเอาแบบไหน จึงหยุดให้คุณเลือก
  • HEAD ตำแหน่งที่คุณอยู่ตอนนี้ คือ branch ที่ git switch มาล่าสุด

Hands-on: สร้าง conflict เองแล้วแก้

บทนี้พิสูจน์ว่าแต่ละ branch เก็บไฟล์คนละฉบับ และเมื่อสอง branch แก้บรรทัดเดียวกัน Git จะไม่เดาให้ แต่หยุดให้คุณตัดสินใจ ทำใน Git Bash ที่โฟลเดอร์ ~/xiao-embedded-cpp

  1. สร้าง branch ใหม่แล้วสลับไปอยู่ (switch -c) เปิด firmware/firmware.ino ด้วย notepad แก้ {500, 0, blinkTask} เป็น {250, 0, blinkTask} บันทึก ปิด แล้ว commit (-a = add ทุกไฟล์ที่แก้, -m = ข้อความ)
  2. กลับไปที่ main แล้วเปิดไฟล์อีกครั้ง จะเห็นว่ายังเป็น 500 เพราะการแก้อยู่บน branch อื่น แก้บรรทัดเดียวกันเป็น {1000, 0, blinkTask} แล้ว commit
  3. รัน git merge จะได้ข้อความ CONFLICT (content): Merge conflict in firmware/firmware.ino
Git Bash
cd ~/xiao-embedded-cpp
git switch -c feature/fast-blink
notepad firmware/firmware.ino      # แก้ 500 เป็น 250 บันทึก ปิด
git commit -am "feat: faster default blink"

git switch main
notepad firmware/firmware.ino      # ยังเป็น 500: แก้เป็น 1000 บันทึก ปิด
git commit -am "chore: slower default blink"

git merge feature/fast-blink       # → CONFLICT
  1. เปิด firmware/firmware.ino อีกครั้ง Git ใส่เครื่องหมายไว้ตรงบรรทัดที่ชนกัน ส่วนระหว่าง <<<<<<< HEAD กับ ======= คือของ branch ที่คุณอยู่ (main) ส่วนระหว่าง ======= กับ >>>>>>> คือของ branch ที่กำลัง merge เข้ามา
  2. เลือกเก็บบรรทัดเดียวที่ต้องการ เช่น {250, 0, blinkTask}, ลบอีกบรรทัดและเครื่องหมาย 3 บรรทัดออกให้หมด แล้วบันทึก
firmware.ino ตอน conflict
<<<<<<< HEAD
  {1000, 0, blinkTask},
=======
  {250, 0, blinkTask},
>>>>>>> feature/fast-blink
  1. รัน git add และ git commit โดยไม่ใส่ -m Git จะเปิด editor ที่เลือกไว้ในบท 15 พร้อมข้อความ Merge branch 'feature/fast-blink' ให้แล้ว แค่บันทึกแล้วปิดหน้าต่าง editor commit จะเสร็จเมื่อปิด editor
  2. รัน git log --oneline --graph --all จะเห็นเส้นของสอง branch มาบรรจบกันเหมือนในรูป แล้วลบ branch ที่ใช้เสร็จแล้ว
Git Bash
git add firmware/firmware.ino
git commit                         # ปิด merge: บันทึกแล้วปิด editor
git log --oneline --graph --all
git branch -d feature/fast-blink

ผลนี้บอกอะไร: ขั้นที่ 2 เห็นว่า main ยังเป็น 500 คือแต่ละ branch แยกกันจริง ส่วนขั้นที่ 3 Git ไม่เลือกค่าให้เอง เพราะการตัดสินว่าค่าไหนถูกเป็นหน้าที่ของคน conflict จึงไม่ใช่ error แต่เป็นคำถามจาก Git ตอบด้วยการแก้ไฟล์แล้ว commit

merge เก็บประวัติตามจริง (มี merge commit) ส่วน git rebase main ย้าย commit ของ branch ไปต่อท้าย main ทำให้ประวัติเป็นเส้นตรง กฎ: ห้าม rebase branch ที่คนอื่นดึงไปแล้ว

เช็กความเข้าใจ

ถ้าแก้ conflict ผิดแล้วอยากเริ่มใหม่ทำอย่างไร?

git merge --abort ก่อน commit จะกลับไปสถานะก่อน merge

ทำไมทีมไม่ commit ตรงเข้า main?

main ควร build ได้และ test ผ่านเสมอ การผ่าน branch + PR ให้ CI และคนอื่นตรวจก่อน และย้อนกลับง่าย
