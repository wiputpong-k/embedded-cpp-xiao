Branch, merge และแก้ conflict

25 นาที · ฮาร์ดแวร์: คอมพิวเตอร์

ในบทนี้
  1. Hands-on: สร้าง conflict เองแล้วแก้

เป้าหมาย แยกงานเป็น branch และแก้ merge conflict ได้โดยไม่ตื่นตระหนก

Hands-on: สร้าง conflict เองแล้วแก้

terminal
git switch -c feature/fast-blink
# ใน firmware.ino แก้ {500, 0, blinkTask} เป็น {250, 0, blinkTask}
git commit -am "feat: faster default blink"

git switch main
# แก้บรรทัดเดียวกันเป็น {1000, 0, blinkTask}
git commit -am "chore: slower default blink"

git merge feature/fast-blink      # → CONFLICT
firmware.ino ตอน conflict
<<<<<<< HEAD
  {1000, 0, blinkTask},
=======
  {250, 0, blinkTask},
>>>>>>> feature/fast-blink
terminal
# แก้ไฟล์ให้เหลือบรรทัดที่ต้องการ ลบเครื่องหมาย <<< === >>> ออก
git add firmware/firmware.ino
git commit                         # ปิด merge
git log --oneline --graph --all
git branch -d feature/fast-blink

merge เก็บประวัติตามจริง (มี merge commit) ส่วน git rebase main ย้าย commit ของ branch ไปต่อท้าย main ทำให้ประวัติเป็นเส้นตรง กฎ: ห้าม rebase branch ที่คนอื่นดึงไปแล้ว

เช็กความเข้าใจ

ถ้าแก้ conflict ผิดแล้วอยากเริ่มใหม่ทำอย่างไร?

git merge --abort ก่อน commit จะกลับไปสถานะก่อน merge

ทำไมทีมไม่ commit ตรงเข้า main?

main ควร build ได้และ test ผ่านเสมอ การผ่าน branch + PR ให้ CI และคนอื่นตรวจก่อน และย้อนกลับง่าย
