คำถามทบทวนก่อนจบคอร์ส

C++ ต่างจาก C ในงาน embedded อย่างไร มีต้นทุนอะไรบ้าง?

ได้ class, RAII, reference, template, constexpr, enum class, namespace ที่ส่วนใหญ่ไม่มี runtime cost ส่วนที่มีต้นทุนคือ virtual (vtable), exceptions, RTTI, heap ผ่าน STL บางตัว จึงเลือกใช้เป็น subset

volatile ใช้เมื่อไหร่ และไม่ได้ช่วยอะไร?

ตัวแปรที่ ISR แก้, register ของ peripheral, ข้อมูลที่แชร์ระหว่าง context ไม่ได้ทำให้ atomic และไม่ใช่ memory barrier

ISR ที่ดีเป็นอย่างไร?

สั้น, ไม่ block, ไม่จอง memory, ตั้ง flag หรือ push ลง ring buffer แล้วให้ main/task ประมวลผล ข้อมูลที่แชร์ต้องป้องกันด้วย critical section

ทำไมเลี่ยง dynamic allocation หลัง init?

fragmentation, เวลาไม่แน่นอน, และ fail ได้ตอนรันไปนาน ๆ ระบบที่ต้องทำงานต่อเนื่องจึงจองทุกอย่างแบบ static

อธิบาย RAII พร้อมตัวอย่าง

ผูกอายุ resource กับ object: CriticalSection ปิด interrupt ใน ctor คืนค่าใน dtor ออกจาก scope ทางไหนก็คืนเสมอ

debounce มีกี่วิธี?

ฮาร์ดแวร์ (RC + Schmitt trigger) และซอฟต์แวร์ (รอให้นิ่งตามเวลา หรือ sample หลายครั้ง) เลือกตามต้นทุน BOM กับ CPU

merge กับ rebase เลือกอย่างไร?

merge เก็บประวัติจริงและปลอดภัยกับ branch ที่แชร์ rebase ทำประวัติเส้นตรง ใช้กับ branch ส่วนตัวก่อนเปิด PR

pipeline CI/CD ของ firmware ควรมีอะไร?

build ทุก target, unit test บน host, static analysis, เก็บ artifact, release ตาม tag พร้อมเวอร์ชันฝังใน binary, ขั้นต่อไปคือ HIL test บน runner ที่ต่อบอร์ดจริง

มุมงานจริง

ประสบการณ์ PCB, failure analysis และ V&V ช่วยงาน firmware ได้มาก ใน README หรือ design note ให้เชื่อม 2 ฝั่ง เช่น อธิบายว่าเลือกค่า R ของ LED และ debounce time จากอะไร คนที่มาอ่านโค้ดทีหลังจะเข้าใจเหตุผล ไม่ใช่เห็นแค่ตัวเลข
