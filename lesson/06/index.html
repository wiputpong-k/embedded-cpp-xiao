RAII และ destructor

เป้าหมาย ใช้ scope ควบคุม resource อัตโนมัติ: จับเวลา, ปิด/เปิด interrupt

ใน C ถ้าปิด interrupt ไว้แล้ว return กลางฟังก์ชันโดยลืมเปิดคืน ระบบจะค้างแบบหาสาเหตุยาก C++ แก้ปัญหานี้ด้วยการผูก "การคืน" ไว้กับการออกจาก { } คำศัพท์ที่ใช้ในบทนี้:

  • resource สิ่งที่ยืมแล้วต้องคืน เช่น สถานะ "ปิด interrupt", lock หรือ buffer ที่จองไว้
  • interrupt สัญญาณที่ทำให้ CPU หยุดงานที่ทำอยู่ชั่วคราวไปทำงานเร่งด่วน เช่น เมื่อมีข้อมูล USB เข้ามา (บท 12 ลงรายละเอียด) บางช่วงต้องปิดไว้สั้น ๆ เพื่อไม่ให้ถูกแทรกกลาง เรียกช่วงนั้นว่า critical section
  • destructor ฟังก์ชัน ~ชื่อclass() ที่ทำงานอัตโนมัติเมื่อ object หมดอายุ object local หมดอายุตอนออกจาก { } ที่ประกาศมัน (scope ในบท 02)

RAII (Resource Acquisition Is Initialization): ขอ resource ใน constructor คืนใน destructor แล้ว compiler จะเรียก destructor ให้เมื่อออกจาก scope เสมอ จึงไม่มีทางลืม unlock หรือเปิด interrupt คืน แม้จะ return กลางทาง C ไม่มีกลไกนี้

ต่อวงจร

potentiometer (pot) คือตัวต้านทานปรับค่าได้ มี 3 ขา ขาสองข้างต่อกับปลายทั้งสองของตัวต้านทาน ส่วนขากลาง (wiper) เลื่อนไปตามการหมุน แรงดันที่ขากลางจึงเปลี่ยนได้ตั้งแต่ 0 ถึง 3.3 V

  1. ถอดสาย USB ออกก่อน (LED จากบท 04 ต่อทิ้งไว้ได้)
  2. เสียบ pot ลง breadboard ให้ 3 ขาอยู่คนละแถว
  3. ต่อขาข้างหนึ่งไปที่ขา 3V3 ของบอร์ด และขาข้างที่เหลือไปที่ GND (สลับกันได้ แค่ทิศการหมุนกลับด้าน)
  4. ต่อขากลางไปที่ขา A0 (ขาเดียวกับ D0)

ใช้ขา 3V3 เท่านั้น ห้ามต่อ 5V เพราะขาของ nRF52840 รับแรงดันได้ไม่เกิน 3.3 V

Hands-on

sketch นี้พิสูจน์ว่า destructor ทำงานเองเมื่อออกจาก { }: ScopedTimer พิมพ์เวลาโดยไม่มีใครสั่งพิมพ์ และ CriticalSection เปิด interrupt คืนให้เองโดยไม่มีบรรทัดเปิดคืน

  1. เสียบ USB กลับ สร้าง sketch ใหม่ วางโค้ดข้างล่าง บันทึกชื่อ raii แล้วกด Upload
  2. เปิด Tools → Serial Monitor ที่ 115200 baud แล้วลองหมุน pot
raii.ino
#include <Adafruit_TinyUSB.h>   // เปิด USB และ Serial (core นี้ต้องมี)
class ScopedTimer {
public:
  explicit ScopedTimer(const char* label) : label_(label), start_(micros()) {}
  ~ScopedTimer() {
    uint32_t us = micros() - start_;
    Serial.print(label_); Serial.print(": "); Serial.print(us); Serial.println(" us");
  }
  ScopedTimer(const ScopedTimer&) = delete;             // ห้าม copy
  ScopedTimer& operator=(const ScopedTimer&) = delete;
private:
  const char* label_;
  uint32_t start_;
};

// ปิด interrupt แบบซ้อนได้: เก็บสถานะเดิมแล้วคืนค่าเดิม
class CriticalSection {
public:
  CriticalSection() : primask_(__get_PRIMASK()) { __disable_irq(); }
  ~CriticalSection() { __set_PRIMASK(primask_); }
private:
  uint32_t primask_;
};

void setup() { Serial.begin(115200); }

void loop() {
  long sum = 0;
  {
    ScopedTimer t("analogRead x100");
    for (int i = 0; i < 100; ++i) sum += analogRead(A0);
  }                                   // destructor ทำงานตรงนี้
  Serial.print("avg = "); Serial.println(sum / 100);

  uint32_t inside;
  {
    CriticalSection cs;               // ปิด interrupt
    inside = __get_PRIMASK();         // 1 = ปิดอยู่
  }                                   // destructor เปิดคืน
  Serial.print("PRIMASK inside = "); Serial.print(inside);
  Serial.print(", after = ");        Serial.println(__get_PRIMASK());
  delay(1000);
}
  • micros() เวลาตั้งแต่บอร์ดเริ่มทำงาน หน่วยไมโครวินาที
  • explicit ห้าม compiler แปลงข้อความเป็น ScopedTimer ให้เองโดยไม่ได้ตั้งใจ ส่วน = delete ห้ามใช้ฟังก์ชันนั้น (ที่นี่คือห้าม copy ดูคำถามข้อแรก)
  • PRIMASK register ใน CPU Cortex-M: 1 = ปิด interrupt, 0 = เปิด __disable_irq() ตั้งเป็น 1 ส่วน __get_PRIMASK() / __set_PRIMASK() อ่านและเขียนค่านี้

ผลที่ควรเห็น ทุก 1 วินาที (ตัวเลข us และ avg ของคุณจะต่างออกไป):

Serial Monitor
analogRead x100: … us
avg = 512
PRIMASK inside = 1, after = 0

ผลนี้บอกอะไร:

  • destructor ทำงานเอง บรรทัด analogRead x100 ไม่มีใครเรียก print ใน loop() มันมาจาก ~ScopedTimer() ที่ทำงานตรง }
  • คืน resource เสมอ inside = 1 คือ interrupt ถูกปิดภายใน { } และ after = 0 คือถูกเปิดคืนแล้ว ทั้งที่ไม่มีบรรทัดเปิดคืนเลย
  • วงจร pot หมุนแล้ว avg เปลี่ยนในช่วง 0–1023 เพราะ analogRead() ใช้ ADC (วงจรในชิปที่แปลงแรงดันเป็นตัวเลข) แปลง 0–3.3 V เป็น 0–1023

อย่าเรียก Serial.print ระหว่างที่ interrupt ปิดอยู่ เพราะ USB ต้องใช้ interrupt จึงเก็บค่าไว้ในตัวแปรก่อนแล้วพิมพ์หลังออกจาก { }

เช็กความเข้าใจ

ทำไมต้อง = delete copy constructor?

ถ้า copy ได้ จะมี 2 object ที่ destructor ทำงานซ้ำ เช่น เปิด interrupt 2 ครั้ง หรือพิมพ์เวลาซ้ำ resource ที่มีเจ้าของคนเดียวควรห้าม copy

CriticalSection ใช้ตอนเปิด BLE ได้ไหม?

ใช้ได้แค่ช่วงสั้นมาก ไม่กี่ไมโครวินาที เพราะ BLE ของ nRF52 ทำงานด้วย SoftDevice (ซอฟต์แวร์วิทยุของ Nordic ที่อยู่ในชิป) ถ้าปิด interrupt นาน SoftDevice จะพลาดจังหวะของวิทยุ ในงานจริงใช้ฟังก์ชันของ SoftDevice เอง (sd_nvic_critical_region_enter) แทน

มุมงานจริง

RAII คือเหตุผลหลักที่หลายทีมย้ายจาก C มา C++ ในงาน embedded เพราะไม่ทำให้โปรแกรมช้าลง และกำจัดบั๊กลืมคืน resource ได้ทั้งกลุ่ม เช่น ลืมเปิด interrupt คืนในทางที่ออกจากฟังก์ชันเพราะเกิด error
