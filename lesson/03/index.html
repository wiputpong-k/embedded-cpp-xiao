C

ชื่อฟังก์ชันซ้ำไม่ได้ ต้องตั้ง log_int, log_float และ enum ปนกับ int ได้ทุกที่

C++

overload ชื่อเดียวหลายพารามิเตอร์ได้ namespace กันชื่อชน enum class ไม่แปลงเป็น int เอง กำหนดขนาด : uint8_t ได้

  • overloading ฟังก์ชันชื่อเดียวกันหลายตัวที่รับพารามิเตอร์ต่างกัน (จำนวนหรือชนิด) compiler เลือกตัวที่ตรงกับค่าที่ส่งเข้าไปให้เอง ถ้าต่างกันแค่ชนิดที่ return ไม่นับเป็น overload
  • namespace กล่องใส่ชื่อ ใส่ได้ทุกอย่างที่มีชื่อ ไม่ใช่แค่ฟังก์ชัน แต่รวมถึงตัวแปร ค่าคงที่ enum และ class เรียกใช้ด้วย กล่อง::ชื่อ เช่น logx::info
  • enum class enum ที่ต้องเรียกเต็ม เช่น Mode::Slow และไม่กลายเป็นตัวเลขเอง ส่วน : uint8_t กำหนดว่าใช้ที่ 1 byte

namespace: แก้ปัญหาชื่อชนกัน

ใน C ทุกชื่ออยู่รวมในที่เดียว ถ้า library สองตัวมีฟังก์ชันชื่อ info เหมือนกัน จะ build ไม่ผ่าน คนเขียน C จึงต้องเติม prefix เอง C++ ใช้ namespace ทำหน้าที่นี้แทน

// C: เติม prefix เองเพื่อไม่ให้ชื่อชนกัน
void logx_info(const char* msg);
void wifi_info(const char* msg);

// C++: ใช้ namespace แทน prefix
namespace logx {
  int level = 1;                // ใส่ตัวแปรได้ด้วย
  void info(const char* msg);
}
namespace wifi {
  void info(const char* msg);   // ชื่อ info ซ้ำได้ เพราะอยู่คนละกล่อง
}

logx::info("boot");
wifi::info("connected");
  • ตัวอย่างจริงในคอร์สนี้ core ของ Seeed มี class ชื่อ RingBuffer อยู่แล้ว บท 10 จึงเก็บ RingBuffer ของเราไว้ใน namespace xiao แล้วเรียกเป็น xiao::RingBuffer เพื่อไม่ให้ชนกับของ core
  • std:: ที่จะเห็นบ่อย ๆ ก็เป็น namespace คือกล่องของ C++ standard library เช่น std::array
  • namespace ไม่ใช่ class namespace แค่จัดกลุ่มชื่อ สร้างเป็น object ไม่ได้ ส่วน class เป็นชนิดข้อมูลที่สร้าง object ได้ (บท 04)

enum class ต่างจาก enum ของ C อย่างไร

enum ใช้ตั้งชื่อให้ชุดตัวเลือกที่รู้ล่วงหน้า เช่น โหมดหรือสถานะ ข้างในยังเป็นตัวเลข 0, 1, 2 … เหมือนเดิม C++ เพิ่ม enum class ที่ตรวจเข้มกว่า เทียบกันได้แบบนี้:

// C: enum ธรรมดา
enum Mode  { OFF, SLOW, FAST };
enum Speed { SLOW, FAST };      // error: SLOW ซ้ำ เพราะชื่อหลุดออกมาข้างนอก
enum Mode m = SLOW;
int x = m;                      // ได้ 1 แปลงเป็น int เองโดยไม่บอก
if (m == 2) {}                  // เทียบกับตัวเลขได้ แต่อ่านไม่รู้ว่า 2 คือโหมดไหน

// C++: enum class
enum class Mode  : uint8_t { Off, Slow, Fast };   // : uint8_t = ใช้ 1 byte
enum class Speed : uint8_t { Slow, Fast };        // ไม่ชน ชื่ออยู่ในกล่องของตัวเอง
Mode m = Mode::Slow;                              // ต้องเรียกชื่อเต็ม
int x = m;                                        // error: ไม่แปลงเป็น int เอง
int y = static_cast<int>(m);                      // ต้องแปลงเองแบบตั้งใจ
  • ชื่อไม่หลุดออกมาข้างนอก enum ของ C ทำให้ SLOW กลายเป็นชื่อกลางที่ใช้ได้ทั้งไฟล์ จึงต้องตั้ง prefix เอง เช่น MODE_SLOW ส่วน enum class เก็บชื่อไว้ในกล่องของตัวเองเหมือน namespace
  • ไม่แปลงเป็นตัวเลขเอง compiler จับ bug ที่เผลอเอาโหมดไปปนกับตัวเลขให้ตั้งแต่ตอน compile ถ้าต้องการตัวเลขจริงให้ใช้ static_cast<int>(m)
  • กำหนดขนาดได้ enum ของ C มีขนาดเท่า int (4 byte บน nRF52840) : uint8_t ทำให้รู้ขนาดแน่นอน เหมาะกับการเก็บใน struct ส่งทาง Serial/BLE หรือบันทึกลง flash

หลัง compile ทั้งสองแบบเป็นตัวเลขเหมือนกัน enum class จึงไม่ทำให้โปรแกรมช้าลง สิ่งที่ได้คือ compiler ตรวจให้เข้มขึ้น

ใช้ enum กับงานแบบไหน

ใช้เมื่อค่ามีตัวเลือกจำนวนจำกัดที่รู้ล่วงหน้า และแต่ละตัวมีความหมาย ไม่ได้เป็นปริมาณที่เอาไปบวกลบ งาน firmware ที่ใช้บ่อย:

  • สถานะของ state machine เช่น Idle, Connecting, Connected (ตัวอย่างข้างล่าง)
  • โหมดหรือการตั้งค่า เช่น Mode::Slow ในบทนี้ หรือระดับ log (Debug, Info, Error)
  • event เช่น Debouncer::Event::Pressed ในบท 07
  • ผลลัพธ์และ error code เช่น Err::Timeout อ่านง่ายกว่า return -3;
  • คำสั่งใน protocol กำหนดเลขเองให้ตรงกับเอกสาร เช่น enum class Cmd : uint8_t { Ping = 0x01, ReadTemp = 0x10 };
enum class State : uint8_t { Idle, Connecting, Connected };
State state = State::Idle;

switch (state) {
  case State::Idle:       /* รอกดปุ่ม */     break;
  case State::Connecting: /* รอเชื่อมต่อ */  break;
  case State::Connected:  /* ส่งข้อมูล */    break;
}

ไม่ควรใช้ enum กับค่าที่เป็นปริมาณ เช่น อุณหภูมิ เวลา หมายเลข pin หรือ baud rate ค่าพวกนี้ใช้ constexpr (บท 02) วิธีจำง่าย ๆ: ถ้าต้องเขียนคอมเมนต์อธิบายตัวเลข เช่น if (state == 2) // 2 = connected แบบนี้ควรเปลี่ยนเป็น enum

name mangling: overload ทำงานได้อย่างไร

ใน C ฟังก์ชันชื่อ info ใน .o ก็ชื่อ info แต่ใน C++ มี info ได้หลายตัว ชื่อนี้จึงไม่พอให้ linker (บท 01) แยกได้ compiler จึงต่อชนิดพารามิเตอร์ลงไปในชื่อ เรียกว่า name mangling ชื่อที่ได้เรียกว่า symbol คือชื่อที่ linker ใช้จับคู่ "คนเรียก" กับ "ตัวฟังก์ชัน" ถ้าหา symbol ไม่เจอ จะได้ error undefined reference เช่น ถ้า sketch ไม่มี setup() linker จะแจ้ง undefined reference to `setup' เพราะ main() ของ core เรียกหาแต่ไม่เจอ

Hands-on

sketch นี้พิสูจน์ว่า info 3 ตัวอยู่ร่วมกันได้ (compiler เลือกตัวตามพารามิเตอร์) และ enum class ไม่ยอมกลายเป็นตัวเลขเอง

  1. สร้าง sketch ใหม่ วางโค้ดข้างล่าง บันทึกชื่อ logx แล้วกด Upload
  2. เปิด Tools → Serial Monitor ที่ 115200 baud ถ้าไม่มีข้อความ กด reset บนบอร์ด 1 ครั้ง
logx.ino
#include <Adafruit_TinyUSB.h>   // เปิด USB และ Serial (core นี้ต้องมี)
namespace logx {
void info(const char* msg) {
  Serial.print("[I] "); Serial.println(msg);
}
void info(const char* key, int value) {
  Serial.print("[I] "); Serial.print(key); Serial.print('='); Serial.println(value);
}
void info(const char* key, float value, int digits = 2) {   // default argument
  Serial.print("[I] "); Serial.print(key); Serial.print('='); Serial.println(value, digits);
}
}  // namespace logx

enum class Mode : uint8_t { Off, Slow, Fast };

void setup() {
  Serial.begin(115200);
  while (!Serial) {}
  logx::info("boot");
  logx::info("uptime_ms", (int)millis());
  logx::info("vbat", 3.71f);
  logx::info("pi", 3.14159f, 4);
  Mode m = Mode::Slow;
  logx::info("mode", static_cast<int>(m));   // ต้อง cast เอง
  // int bad = m;   // ลองเปิดบรรทัดนี้: compile error
}

void loop() {}

อ่านโค้ดทีละส่วน:

  • const char* msg ข้อความ "boot" ถูกเก็บเป็น array ของ char ที่ปิดท้ายด้วย '\0' ('b' 'o' 'o' 't' '\0') ตอนส่งเข้าฟังก์ชันจะไม่คัดลอกข้อความทั้งก้อน แต่ส่งแค่ address ของตัวอักษรตัวแรก char* คือ pointer ที่เก็บ address นั้น และ const แปลว่าฟังก์ชันอ่านได้อย่างเดียว ใช้ char msg เฉย ๆ ไม่ได้ เพราะ char เก็บได้แค่ตัวอักษรเดียว ('b') ถ้าเขียนแบบนั้น info("boot") จะ compile error
  • millis() ฟังก์ชันของ Arduino core เหมือน delay() ใช้ได้ทุก sketch โดยไม่ต้อง include อะไรเพิ่ม คืนค่าเป็นจำนวนมิลลิวินาทีนับตั้งแต่บอร์ดเริ่มทำงาน ชนิด uint32_t (จำนวนเต็มไม่ติดลบ 32 บิต) จะใช้จริงในบท 07–08
  • (int)millis() (int) คือการแปลงชนิดแบบ C ต้องใส่เพราะ logx::info มีทั้งตัวที่รับ int และตัวที่รับ float ถ้าส่ง uint32_t เข้าไปตรง ๆ compiler แปลงเป็นได้ทั้งสองแบบและเลือกไม่ได้ จะได้ error: call of overloaded 'info(...)' is ambiguous ค่าบวกที่ int เก็บได้สูงสุดเท่ากับราว 24.8 วัน หลังจากนั้นจะกลายเป็นค่าลบ แต่ตัวอย่างนี้ไม่ต้องห่วง
  • default argument int digits = 2 ถ้าผู้เรียกไม่ส่งค่านี้มา จะใช้ 2
  • static_cast<int>(m) การแปลงชนิดแบบ C++ ทำหน้าที่เหมือน (int)m ของ C แต่ชัดเจนกว่าว่าตั้งใจแปลง

ผลที่ควรเห็น (ตัวเลข uptime_ms ขึ้นกับว่าเปิด Serial Monitor เมื่อไร):

Serial Monitor
[I] boot
[I] uptime_ms=1234
[I] vbat=3.71
[I] pi=3.1416
[I] mode=1

ผลนี้บอกอะไร:

  • overloading ทุกบรรทัดเรียก logx::info ชื่อเดียวกัน แต่รูปแบบที่พิมพ์ต่างกันตามพารามิเตอร์ vbat ได้ทศนิยม 2 ตำแหน่งจาก default argument ส่วน pi ได้ 4 ตำแหน่งตามที่ส่งไป
  • enum class mode=1 เพราะ Slow เป็นตัวที่สอง (นับจาก 0) แต่ต้องแปลงเองด้วย static_cast ลองลบ // หน้าบรรทัด int bad = m; แล้วกด Verify จะได้ error: cannot convert 'Mode' to 'int' in initialization แล้วใส่ // กลับ
  • ambiguous ลองลบ (int) หน้า millis() แล้วกด Verify จะเห็น error ว่า call of overloaded info is ambiguous แล้วใส่ (int) กลับ

เช็กความเข้าใจ

ถ้า library เขียนด้วย C ต้อง include อย่างไร?

ครอบ header ด้วย extern "C" { … } เพื่อปิด name mangling ให้ฟังก์ชันเหล่านั้น linker จึงหา symbol ชื่อแบบ C เจอ ถ้าไม่ครอบจะ error undefined reference

ถ้าเพิ่ม int info(const char* msg) ที่ต่างจากตัวเดิมแค่ชนิดที่ return จะ compile ผ่านไหม?

ไม่ผ่าน ตอนเรียก info("boot") compiler ดูแค่ค่าที่ส่งเข้าไป ซึ่งเหมือนกันทั้งสองตัว จึงแยกไม่ได้ overload ต้องต่างกันที่พารามิเตอร์

หมายเลข pin ของ LED ควรเก็บเป็น enum class หรือ constexpr?

constexpr เพราะ pin เป็นตัวเลขที่ต้องส่งให้ digitalWrite() ตรง ๆ ถ้าเป็น enum class ต้อง static_cast ทุกครั้งที่ใช้ enum เหมาะกับชุดตัวเลือกที่มีความหมาย เช่น โหมดหรือสถานะ
