ติดตั้ง Git และ commit แรก

เป้าหมาย ติดตั้ง Git แล้วเก็บงานทั้งหมดที่ทำมาลง repo พร้อม commit message ที่อ่านแล้วรู้เรื่อง

Git คือโปรแกรมเก็บประวัติการแก้โค้ด ทุกครั้งที่ commit คือการถ่ายภาพไฟล์ทั้งหมด ณ เวลานั้นไว้ ย้อนกลับไปดูหรือกู้คืนได้เสมอ ใช้ตั้งแต่บทนี้ไปจนจบคอร์ส

ขั้นที่ 1: ติดตั้ง Git

  1. (ไม่บังคับ) ถ้าอยากใช้ VS Code เป็นโปรแกรมแก้ข้อความ ให้ติดตั้งจาก code.visualstudio.com ก่อน เพราะตัวติดตั้ง Git จะถามหาโปรแกรมนี้
  2. เปิดหน้า git-scm.com/downloads/win แล้วดาวน์โหลดตัวติดตั้ง Git for Windows แบบ 64-bit
  3. เปิดตัวติดตั้ง แล้วกด Next ตามค่าเริ่มต้น ยกเว้น 2 หน้านี้
    • Choosing the default editor used by Git: เลือก Use Visual Studio Code as Git's default editor ถ้าติดตั้ง VS Code แล้ว หรือเลือก Use Notepad as Git's default editor ถ้าไม่ได้ติดตั้ง
    • Adjusting the name of the initial branch: เลือก Override the default branch name แล้วพิมพ์ main
  4. กด Install แล้วรอจนเสร็จ

ทำไมต้องเลือก editor: บางคำสั่งของ Git จะเปิดโปรแกรมแก้ข้อความให้คุณพิมพ์ เช่น git commit ที่ไม่ใส่ -m หรือตอน merge ในบท 16 ค่าเริ่มต้นของ Git คือ Vim ซึ่งคนที่ไม่เคยใช้มักออกจากโปรแกรมไม่เป็น VS Code หรือ Notepad ใช้ง่ายกว่า เลือกตัวไหนก็ได้ ไม่มีผลกับเนื้อหาในคอร์ส

ขั้นที่ 2: เปิด Git Bash และบอก Git ว่าคุณเป็นใคร

ตัวติดตั้ง Git มีโปรแกรม Git Bash มาด้วย เป็น terminal ที่ใช้คำสั่งแบบเดียวกับ Linux และ macOS คำสั่งทั้งหมดตั้งแต่บทนี้ไปให้พิมพ์ใน Git Bash (กดปุ่ม Windows พิมพ์ Git Bash แล้วกด Enter) macOS และ Linux ใช้ Terminal ปกติได้เลย

รัน 3 บรรทัดแรกของคำสั่งข้างล่าง โดยเปลี่ยนชื่อและอีเมลเป็นของคุณ ข้อมูลนี้จะติดไปกับทุก commit และจะเห็นได้สาธารณะเมื่อ push ขึ้น GitHub ถ้าไม่อยากเปิดเผยอีเมลจริง ใช้อีเมลแบบ noreply ที่ GitHub ให้ได้ (ดูที่ GitHub → Settings → Emails)

เช็ก: รัน git --version ต้องเห็นข้อความแบบ git version 2.xx.x.windows.1

Git Bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
git --version

ขั้นที่ 3: สร้าง repo และนำงานจากบท 13–14 เข้ามา

  1. รันคำสั่งชุดข้างล่างทีละบรรทัด จะได้โฟลเดอร์ xiao-embedded-cpp ในโฟลเดอร์ผู้ใช้ของคุณ (~) พร้อม repo Git เปล่า
  2. บรรทัด cp -r คัดลอก sketch firmware จากบท 13–14 เข้ามา ถ้า sketch ไม่ได้อยู่ที่ Documents/Arduino ให้ดูตำแหน่งจริงใน Arduino IDE ที่ File → Preferences → Sketchbook location (ถ้าใช้ OneDrive มักเป็น ~/OneDrive/Documents/Arduino)
Git Bash
cd ~
mkdir xiao-embedded-cpp
cd xiao-embedded-cpp
git init
cp -r ~/Documents/Arduino/firmware .
ls firmware firmware/src

ขั้นที่ 4: บอก Git ว่าไฟล์ไหนไม่ต้องเก็บ

ไฟล์ที่ build สร้างขึ้นใหม่ได้ เช่น .hex หรือโปรแกรม test ไม่ควรเข้า repo รัน notepad .gitignore (หรือ code .gitignore ถ้าใช้ VS Code) ถ้าถามว่าจะสร้างไฟล์ใหม่ไหม ให้ตอบ Yes แล้ววางเนื้อหาข้างล่าง บันทึก แล้วปิด

.gitignore
build/
*.hex
*.zip
*.uf2
firmware/src/version.h
test_runner
test_runner.exe
.vscode/

ขั้นที่ 5: commit แรก

git status แสดงว่าไฟล์ไหนเปลี่ยนไปบ้าง git add เลือกไฟล์เข้า staging area แล้ว git commit เก็บเป็นภาพถ่ายถาวร

Git Bash
git status
git add .gitignore firmware/
git commit -m "feat: led, debouncer, ring buffer and task scheduler"
git log --oneline

# แก้ไฟล์แล้วลอง:
git diff              # สิ่งที่แก้ แต่ยังไม่ add
git add -p            # เลือก add ทีละก้อน
git restore <file>    # ทิ้งการแก้ไขที่ยังไม่ add

ลองแก้ตัวเลขใน tasks[] ของ firmware/firmware.ino แล้วรัน git diff ดูสิ่งที่เปลี่ยน จากนั้นรัน git restore firmware/firmware.ino เพื่อทิ้งการแก้ไขนั้น

รูปแบบ commit message ที่ทีมนิยม (Conventional Commits): feat: ฟีเจอร์ใหม่, fix: แก้บั๊ก, docs:, test:, ci:, refactor: หนึ่ง commit = หนึ่งเรื่อง

เช็กความเข้าใจ

ทำไมไม่ควร commit ไฟล์ .hex?

เป็นผลลัพธ์ที่สร้างซ้ำได้จาก source เปลี่ยนทุก build ทำให้ repo บวมและ diff อ่านไม่ได้ ไฟล์ binary ควรอยู่ใน GitHub Release (บท 23)

git add . กับ git add -p ต่างกันอย่างไร?

add . เอาทุกการเปลี่ยนแปลง -p ให้เลือกทีละ hunk ช่วยแยก commit ตามเรื่องได้ แม้แก้หลายเรื่องในไฟล์เดียว
