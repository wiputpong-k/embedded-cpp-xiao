CI 2: compile firmware ใน CI

30 นาที · ฮาร์ดแวร์: คอมพิวเตอร์

ในบทนี้
  1. ขั้นที่ 1: หาค่า FQBN ด้วย arduino-cli
  2. ขั้นที่ 2: เพิ่ม job build-firmware
  3. ขั้นที่ 3: บังคับให้ PR ต้องผ่าน CI
  4. เช็กความเข้าใจ

เป้าหมาย เพิ่ม job ที่ compile firmware ทุกครั้งหลัง test ผ่าน และบังคับให้ PR ต้องผ่าน CI ก่อน merge

บทที่แล้ว CI รัน test ของ logic แต่ยังไม่รู้ว่า firmware ทั้งก้อน compile ผ่านหรือเปล่า บทนี้พิสูจน์ว่า firmware build ได้บนเครื่องเปล่าที่ไม่ใช่เครื่องเรา (ไม่ใช่แค่ "ในเครื่องผมได้") และ PR ที่ทำให้ build พังจะ merge ไม่ได้

ขั้นที่ 1: หาค่า FQBN ด้วย arduino-cli

CI ไม่มี Arduino IDE ให้กด จึงใช้ arduino-cli คือ Arduino แบบสั่งงานด้วยคำสั่งพิมพ์ (Arduino IDE 2 เองก็เรียก arduino-cli อยู่เบื้องหลัง) ต้องบอกชื่อเต็มของบอร์ดที่เรียกว่า FQBN (Fully Qualified Board Name) ในรูป ผู้ผลิต:สถาปัตยกรรม:บอร์ด บรรทัดแรกของ verbose output ในบท 01 ก็แสดงค่านี้

  1. Arduino IDE 2 มี arduino-cli มาให้แล้ว และใช้ core ที่ติดตั้งไว้ในบท 00 ตัวเดียวกัน เปิด PowerShell แล้วรันคำสั่งข้างล่าง (ถ้าติดตั้ง IDE ไว้ที่อื่น ให้แก้ path ให้ตรง)
  2. มองหาบรรทัด Seeed XIAO nRF52840 Sense ค่า FQBN คือ Seeeduino:nrf52:xiaonRF52840Sense ถ้าบอร์ดของคุณไม่ใช่รุ่น Sense ให้ใช้ค่าของรุ่นนั้นแทน

macOS / Linux หรือไม่ได้ใช้ Arduino IDE 2: ดาวน์โหลด arduino-cli จาก github.com/arduino/arduino-cli/releases แล้วรัน core install Seeeduino:nrf52 --additional-urls … ก่อน board listall แบบเดียวกับขั้น Install board core ใน ci.yml ข้างล่าง

PowerShell
& "C:\Program Files\Arduino IDE\resources\app\lib\backend\resources\arduino-cli.exe" board listall xiao

ขั้นที่ 2: เพิ่ม job build-firmware

  1. ใน Git Bash สร้าง branch ใหม่ แล้วเปิด .github/workflows/ci.yml แทนที่เนื้อหาทั้งหมดด้วยไฟล์ข้างล่าง (ส่วน env: และ job build-firmware เป็นของใหม่) ถ้า FQBN ที่ได้จากขั้นที่ 1 ต่างจากในไฟล์ ให้แก้ให้ตรง
  2. commit, push, เปิด PR แล้วรอ job ทั้งสองเป็นสีเขียว job ที่สองใช้เวลานานกว่าเพราะต้องดาวน์โหลด core
  3. เปิดหน้า run ในแท็บ Actions เลื่อนลงไปที่ส่วน Artifacts ดาวน์โหลด firmware แล้วดูว่ามีไฟล์ .hex และ .zip
  4. merge PR
.github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:

env:
  BOARD_URL: https://files.seeedstudio.com/arduino/package_seeeduino_boards_index.json
  FQBN: Seeeduino:nrf52:xiaonRF52840Sense   # ใช้ค่าที่ได้จาก board listall

jobs:
  host-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build tests
        run: g++ -std=c++17 -Wall -Wextra -Werror -Ifirmware/src test/test_main.cpp -o test_runner
      - name: Run tests
        run: ./test_runner
      - name: Static analysis
        run: |
          sudo apt-get update && sudo apt-get install -y cppcheck
          cppcheck --error-exitcode=1 --enable=warning,performance --std=c++17 -Ifirmware/src test/test_main.cpp

  build-firmware:
    needs: host-tests
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      - run: pip install adafruit-nrfutil   # core ใช้ตอนแพ็ก .zip บน Linux
      - uses: arduino/setup-arduino-cli@v2
      - name: Install board core
        run: |
          arduino-cli core update-index --additional-urls "$BOARD_URL"
          arduino-cli core install Seeeduino:nrf52 --additional-urls "$BOARD_URL"
      - name: Compile
        run: arduino-cli compile --fqbn "$FQBN" --additional-urls "$BOARD_URL" --output-dir out firmware
      - uses: actions/upload-artifact@v4
        with:
          name: firmware
          path: out/

ส่วนที่เพิ่มจากบท 21:

  • env: ตัวแปรที่ทุก job ใช้ร่วมกัน เรียกในคำสั่งด้วย "$BOARD_URL" และ "$FQBN" แก้ที่เดียวพอ
  • needs: host-tests ให้ job นี้รอจน host-tests ผ่านก่อนค่อยเริ่ม
  • setup-python + pip install adafruit-nrfutil เครื่องมือที่ core ใช้แพ็กไฟล์ .zip สำหรับ bootloader (บท 23) บน Linux ต้องติดตั้งเอง
  • setup-arduino-cli และขั้น Install board core ติดตั้ง arduino-cli และ core ของ Seeed ทุกครั้ง เพราะ runner เป็นเครื่องเปล่า เทียบได้กับ Boards Manager ในบท 00
  • Compile คือปุ่ม Verify ของ IDE ในรูปคำสั่ง --output-dir out ให้เก็บผลลัพธ์ (.hex, .zip) ไว้ในโฟลเดอร์ out
  • upload-artifact เก็บโฟลเดอร์ out ไว้กับ run นั้นในชื่อ firmware ไฟล์ที่ได้จากการ build แบบนี้เรียกว่า artifact
Git Bash
git switch -c ci/build-firmware
# แก้ ci.yml แล้วบันทึก จากนั้น:
git add .github/
git commit -m "ci: compile firmware after host tests"
git push -u origin ci/build-firmware
gh pr create --fill
gh pr checks --watch

ขั้นที่ 3: บังคับให้ PR ต้องผ่าน CI

  1. บน GitHub ไปที่ Settings → Branches แล้วแก้กฎของ main ที่สร้างไว้ในบท 18
  2. เปิด Require status checks to pass before merging แล้วค้นหาและเพิ่ม host-tests กับ build-firmware แล้วบันทึก
  3. ใส่ badge แสดงสถานะ CI ไว้บนสุดของ README (เปลี่ยน <user> เป็นชื่อบัญชี GitHub ของคุณ) แล้ว commit ผ่าน PR
README.md
![CI](https://github.com/<user>/xiao-embedded-cpp/actions/workflows/ci.yml/badge.svg)

ถ้า compile ใน CI ล้มที่ขั้น packaging ให้ดูว่าติดตั้ง adafruit-nrfutil แล้ว และ FQBN ตรงกับที่ arduino-cli board listall xiao แสดง เวอร์ชัน core ควร pin ด้วย Seeeduino:nrf52@x.y.z เพื่อให้ build ซ้ำได้เหมือนเดิม

เช็กความเข้าใจ

needs: host-tests มีไว้ทำไม?

ให้ build-firmware รันหลัง test ผ่านเท่านั้น ประหยัดเวลาและสื่อลำดับความสำคัญ ถ้าไม่ใส่ 2 job จะรันขนานกัน

ทำไมต้อง pin เวอร์ชัน core / action?

ให้ build ซ้ำเมื่อไรก็ได้ firmware เหมือนเดิม ถ้า core อัปเดตเอง firmware อาจทำงานต่างไปโดยไม่มีใครแก้โค้ด เป็นหลักเดียวกับการล็อกรุ่นชิ้นส่วนใน BOM (รายการชิ้นส่วน) ของฮาร์ดแวร์

มุมงานจริง

ในทีม CI กับ CD มักถูกพูดปนกัน: CI = รวมโค้ดบ่อยและตรวจอัตโนมัติทุกครั้ง, CD = ส่งมอบ artifact ที่พร้อมใช้อัตโนมัติ (บทถัดไป) แยกให้ชัดแล้วจะคุยเรื่อง pipeline กันง่ายขึ้น
