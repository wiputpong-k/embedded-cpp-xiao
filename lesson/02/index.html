Reference, const และ constexpr แทน #define

เป้าหมาย เลิกใช้ #define กับค่าคงที่ และส่งพารามิเตอร์ด้วย reference ได้ถูกที่

ใน C ค่าคงที่มักเขียนเป็น #define LED_COUNT 3 ซึ่ง preprocessor (ขั้นแรกของ build ในบท 01) แค่แทนข้อความ LED_COUNT ด้วย 3 ก่อน compile ตัวเลขนั้นจึงไม่มี type และไม่มี scope C++ มีทางที่ดีกว่า และมี reference ที่ใช้แทน pointer ได้ในหลายกรณี

C

ค่าคงที่ใช้ #define ไม่มี type ไม่มี scope แก้ตัวแปรของผู้เรียกต้องส่ง pointer

C++

constexpr มี type และคำนวณตอน compile ไม่กิน RAM ส่วน T& คือชื่อเล่นของตัวแปรเดิม ไม่มี null ไม่ต้องเขียน *

  • compile time / runtime ค่าที่รู้ตอน compile (บน PC ก่อนลงบอร์ด) เทียบกับค่าที่รู้ตอนโปรแกรมทำงานบนบอร์ด ค่าที่รู้ตอน compile ไม่ต้องคำนวณบนชิปและไม่ต้องเก็บใน RAM
  • scope ขอบเขตที่ชื่อหนึ่งใช้ได้ เช่น ภายใน { } ของฟังก์ชัน #define ไม่สน scope ใช้ได้ทั้งไฟล์หลังบรรทัดที่ประกาศ
  • reference (T&) ชื่อที่สองของตัวแปรเดิม แก้ผ่าน reference = แก้ตัวแปรเดิม เหมือนส่ง pointer แต่ไม่ต้องเขียน & ตอนเรียกและ * ตอนใช้
  • constexpr ย่อจาก constant expression อ่านว่า "คอนสต์-เอ็กซ์-เพอร์" แปลว่าค่าคงที่ที่ compiler คำนวณเสร็จตั้งแต่ตอน compile

ทำไม constexpr ดีกว่า #define

ผลลัพธ์บนบอร์ดเหมือนกัน คือตัวเลขถูกฝังลงในโค้ดและไม่กิน RAM แต่ #define เป็นแค่การแทนข้อความ ส่วน constexpr เป็นค่าที่ compiler รู้จักจริง จึงช่วยจับผิดได้ ตัวอย่างที่เห็นชัดที่สุด:

#define SIZE 2 + 3
int a = SIZE * 2;             // แทนข้อความเป็น 2 + 3 * 2 = 8 (ไม่ใช่ 10!)

constexpr int kSize = 2 + 3;
int b = kSize * 2;            // = 10 ถูกต้อง

constexpr uint8_t kBad = 300; // error: 300 ใหญ่เกิน uint8_t (0-255)
  • มี type compiler ตรวจว่าค่าใส่ใน type ได้ไหม #define ไม่มี type จึงไม่มีใครตรวจ
  • มี scope #define แทนคำนั้นทุกที่หลังบรรทัดที่ประกาศ รวมถึงในไฟล์ที่ include ตามมา ถ้าชื่อไปชนกับชื่อใน library จะพังแบบหาสาเหตุยาก
  • error อ่านรู้เรื่อง error และ debugger แสดงชื่อ kSize ส่วน #define จะเห็นแค่ตัวเลขที่ถูกแทนไปแล้ว

#define ยังใช้กับงานของ preprocessor เช่น include guard (#ifndef FOO_H) หรือเปิด/ปิดโค้ดด้วย #ifdef DEBUG แต่ค่าคงที่ให้ใช้ constexpr

ส่งค่า (copy) กับส่ง reference

void addCopy(size_t n) { n = n + 1; }   // ได้สำเนา: แก้แล้วตัวจริงไม่เปลี่ยน
void addRef(size_t& n)  { n = n + 1; }   // ได้ตัวจริง: แก้แล้วตัวจริงเปลี่ยน

size_t i = 0;
addCopy(i);   // i ยังเป็น 0
addRef(i);    // i เป็น 1

เปรียบเหมือนเอกสาร: ส่งค่า = ถ่ายสำเนาให้ไป ใครขีดเขียนต้นฉบับก็ไม่เปลี่ยน ส่วนส่ง reference = ยื่นต้นฉบับให้เลย เลือกใช้แบบนี้:

  • ต้องแก้ตัวแปรของผู้เรียก → T&
  • แค่อ่าน และเป็นชนิดเล็ก (int, size_t, float, bool, pointer) → ส่งค่าตรง ๆ copy ของเล็กเร็วพอ ๆ กับ reference
  • แค่อ่าน แต่ข้อมูลใหญ่ (struct, String, buffer) → const T& ไม่ต้อง copy ทั้งก้อน ประหยัด RAM และ const กันไม่ให้เผลอแก้

ถ้าฟังก์ชันคืนผลได้ค่าเดียว การ return มักอ่านง่ายกว่าแก้ผ่าน reference

Hands-on

sketch นี้พิสูจน์ 3 เรื่อง: constexpr ใช้เป็นขนาด array และคำนวณตอน compile ได้, reference แก้ตัวแปรของผู้เรียกได้โดยไม่ใช้ pointer และ const ให้ compiler จับบั๊กให้

  1. สร้าง sketch ใหม่ (File → New Sketch) วางโค้ดข้างล่าง แล้วบันทึกชื่อ rgb_cycle
  2. กด Upload ผลที่ควรเห็น: LED บนบอร์ดเปลี่ยนสีวน แดง → เขียว → น้ำเงิน ทุก 0.15 วินาที
rgb_cycle.ino
#include <Adafruit_TinyUSB.h>   // เปิด USB และ Serial (core นี้ต้องมี)
constexpr uint8_t kLedPins[] = {LED_RED, LED_GREEN, LED_BLUE};
constexpr size_t  kLedCount  = sizeof(kLedPins) / sizeof(kLedPins[0]);
constexpr uint32_t kStepMs   = 150;

void allOff() {
  for (uint8_t pin : kLedPins) {   // range-based for (C++11)
    digitalWrite(pin, HIGH);
  }
}

void nextIndex(size_t& idx) {      // reference: แก้ตัวแปรของผู้เรียกได้เลย
  idx = (idx + 1) % kLedCount;
}

size_t current = 0;

void setup() {
  for (uint8_t pin : kLedPins) pinMode(pin, OUTPUT);
  allOff();
}

void loop() {
  allOff();
  digitalWrite(kLedPins[current], LOW);
  delay(kStepMs);
  nextIndex(current);
}
  • uint8_t, uint32_t ชนิดข้อมูลที่ระบุขนาดชัด (8 และ 32 bit) ใช้แทน int ที่ขนาดเปลี่ยนตามบอร์ด (บท 01)
  • size_t เป็น type (ไม่ใช่ตัวแปร) จำนวนเต็มไม่ติดลบ ใช้เก็บขนาดหรือจำนวน/index บน XIAO มีขนาด 32 bit และเป็น type ของผลลัพธ์จาก sizeof
  • sizeof(kLedPins) / sizeof(kLedPins[0]) = ขนาดทั้ง array หารด้วยขนาดของ 1 ช่อง = จำนวนช่อง ที่นี่ได้ 3 / 1 = 3 (uint8_t ช่องละ 1 byte) ใช้ได้เฉพาะกับ array ตัวจริง ถ้าส่ง array เข้าฟังก์ชันจะกลายเป็น pointer และสูตรนี้ผิด
  • (idx + 1) % kLedCount % คือหารเอาเศษ idx จึงวน 0 → 1 → 2 → 0 (เพราะ 3 % 3 = 0) ไม่เกินจำนวน LED
  • for (uint8_t pin : kLedPins) คือ range-based for ของ C++11 วนทุกตัวใน array โดยไม่ต้องเขียน index เอง
  • เขียน HIGH = ดับ และ LOW = ติด เพราะ LED บนบอร์ดเป็น active-LOW (บท 00)

ผลนี้บอกอะไร:

  • reference สีเปลี่ยนได้เพราะ nextIndex(current) แก้ current ตัวจริง ถ้าเป็น C ต้องเขียน nextIndex(&current) และ *idx = ...
  • constexpr kLedCount = 3 ถูกคำนวณตอน compile จาก sizeof ถ้าเพิ่มขาใน kLedPins ค่านี้จะตามเองโดยไม่ต้องแก้ตัวเลข

ลอง const: เพิ่มฟังก์ชันนี้ไว้เหนือ setup() แล้วกด Verify

เพิ่มใน rgb_cycle.ino
#include <Adafruit_TinyUSB.h>   // เปิด USB และ Serial (core นี้ต้องมี)
void printPin(const uint8_t& p) {
  p = 0;
}

compiler จะไม่ยอม compile และแจ้ง error: assignment of read-only reference 'p' นี่คือประโยชน์ของ const: บั๊กถูกจับตอน compile ไม่ใช่ตอนบอร์ดทำงาน (ใช้ const uint8_t& ที่นี่เพื่อการทดลองเท่านั้น ชนิดเล็กแบบนี้ปกติส่งค่าตรง ๆ ดูคำถามข้อแรกด้านล่าง) ลองแล้วลบฟังก์ชันนี้ออก

เช็กความเข้าใจ

เมื่อไหร่ควรส่ง const T& แทนส่งค่า?

เมื่อ T ใหญ่กว่า register (ช่องเก็บข้อมูลใน CPU ขนาด 32 bit) เช่น struct หรือ buffer เพื่อเลี่ยงการ copy ส่วน int, float, pointer ส่งค่าตรง ๆ เร็วกว่าและอ่านง่ายกว่า

constexpr ต่างจาก const อย่างไร?

const = ห้ามแก้ แต่อาจรู้ค่าตอน runtime ส่วน constexpr = ต้องรู้ค่าตอน compile จึงใช้เป็นขนาด array ได้ (และใช้กับ template ในบท 10)

มุมงานจริง

ใน code review ของทีม firmware ค่าคงที่แบบ #define มักถูกขอให้เปลี่ยนเป็น constexpr เพราะ #define ไม่มี type checking, ไม่เคารพ namespace/scope, debugger มองไม่เห็นชื่อ และอาจเกิด side effect จาก macro expansion
