Inheritance, virtual และ interface

25 นาที · ฮาร์ดแวร์: Pot ที่ A0

ในบทนี้
  1. Hands-on
  2. เช็กความเข้าใจ

เป้าหมาย ออกแบบ interface ISensor ให้สลับเซนเซอร์จริงกับเซนเซอร์ปลอมได้ และรู้ต้นทุนของ virtual

สมมติ firmware ต้องอ่านเซนเซอร์หลายแบบ และตอน test อยากใช้เซนเซอร์ปลอมแทนของจริง โดยไม่ต้องแก้โค้ดที่เรียกใช้ ใน C ทำได้ด้วย struct ที่เก็บ function pointer ไว้เอง ใน C++ ใช้ virtual แล้ว compiler สร้างตารางนั้นให้ คำศัพท์ในบทนี้:

  • inheritance class ใหม่รับทุกอย่างจาก class เดิม เขียนว่า class PotSensor : public ISensor class เดิมเรียกว่า base ส่วน class ใหม่เรียกว่า derived
  • virtual / override virtual บอกว่าฟังก์ชันนี้ derived เขียนทับได้ override บอกว่ากำลังเขียนทับ (ถ้าชื่อหรือพารามิเตอร์ไม่ตรง compiler จะแจ้ง error)
  • pure virtual / interface = 0 คือฟังก์ชันที่ base ไม่มีตัวจริง derived ต้องเขียนเอง class ที่มีแต่ฟังก์ชันแบบนี้เรียกว่า interface ใช้เป็น "สัญญา" ว่าเซนเซอร์ทุกตัวต้องมี name() และ read()
  • polymorphism เรียกผ่าน pointer ชนิด base (ISensor*) แต่ฟังก์ชันที่ทำงานเป็นของชนิดจริงของ object
  • vtable / vptr vtable คือตาราง address ของฟังก์ชัน virtual มี 1 ตารางต่อ class เก็บใน flash ส่วน vptr คือ pointer ที่ซ่อนอยู่ในทุก object ชี้ไปที่ vtable ของ class นั้น

Hands-on

sketch นี้พิสูจน์ polymorphism: loop() เรียก s->read() บรรทัดเดียว แต่ได้ค่าจากเซนเซอร์ 2 ชนิด ใช้วงจร pot จากบท 06

  1. สร้าง sketch ใหม่ วางโค้ดข้างล่าง บันทึกชื่อ sensors แล้วกด Upload
  2. เปิด Tools → Serial Plotter ตั้ง 115200 baud แล้วหมุน pot
sensors.ino
#include <Adafruit_TinyUSB.h>   // เปิด USB และ Serial (core นี้ต้องมี)
class ISensor {
public:
  virtual ~ISensor() = default;
  virtual const char* name() const = 0;   // pure virtual = ต้อง override
  virtual float read() = 0;
};

class PotSensor : public ISensor {
public:
  explicit PotSensor(uint8_t pin) : pin_(pin) {}
  const char* name() const override { return "pot"; }
  float read() override { return analogRead(pin_) * (100.0f / 1023.0f); }  // %
private:
  uint8_t pin_;
};

class FakeSensor : public ISensor {
public:
  const char* name() const override { return "fake"; }
  float read() override { t_ += 0.1f; return 50.0f + 40.0f * sinf(t_); }
private:
  float t_ = 0;
};

PotSensor pot(A0);
FakeSensor fake;
ISensor* sensors[] = {&pot, &fake};

void setup() { Serial.begin(115200); }

void loop() {
  for (ISensor* s : sensors) {
    Serial.print(s->name()); Serial.print(':');
    Serial.print(s->read()); Serial.print(' ');
  }
  Serial.println();
  delay(50);
}

ผลที่ควรเห็น: กราฟ 2 เส้น เส้น pot ขึ้นลง 0–100 ตามที่หมุน และเส้น fake เป็นคลื่น sine ระหว่าง 10–90 (Serial Plotter อ่านรูปแบบ ชื่อ:ค่า ในแต่ละบรรทัดเป็นเส้นกราฟ)

ผลนี้บอกอะไร:

  • polymorphism s เป็น ISensor* ทั้งสองรอบ แต่รอบแรกได้ PotSensor::read() รอบสองได้ FakeSensor::read() เพราะแต่ละ object ชี้ไปที่ vtable ของ class ตัวเองตามรูป
  • สลับได้โดยไม่แก้ผู้เรียก จะเพิ่มเซนเซอร์ใหม่ แค่เขียน class ที่สืบจาก ISensor แล้วใส่ใน sensors[] โดย loop() ไม่ต้องแก้เลย นี่คือเหตุผลที่เซนเซอร์ปลอมใช้แทนของจริงตอน test ได้ (บท 20)

เช็กความเข้าใจ

ทำไม base class ต้องมี virtual destructor?

ถ้าทำลาย object ผ่าน pointer ชนิด base (เช่น delete) แล้ว destructor ไม่ virtual destructor ของ derived จะไม่ถูกเรียก resource ที่มันถืออยู่จึงไม่ถูกคืน

ถ้าไม่อยากจ่ายต้นทุน virtual มีทางเลือกอะไร?

ใช้ template (บท 10) ให้ compiler รู้ชนิดจริงตอน compile จึงเรียกฟังก์ชันตรง ๆ ได้ แลกกับ flash ที่อาจเพิ่มขึ้น เพราะได้โค้ด 1 ชุดต่อชนิด

มุมงานจริง

virtual call ต้องอ่าน vptr และ vtable ก่อนแล้วจึงกระโดดไปเรียก เพิ่มเวลาแค่ไม่กี่ cycle (จังหวะ clock บท 01) บน Cortex-M4 ต้นทุนที่สำคัญกว่าคือ compiler นำตัวฟังก์ชันไปแปะแทนการเรียก (inline) ไม่ได้ จึงเลี่ยง virtual เฉพาะในโค้ดที่ถูกเรียกถี่มาก ๆ หรือใน ISR (บท 12) ที่เหลือใช้ได้ตามสบาย
