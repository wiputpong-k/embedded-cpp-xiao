Pull Request

25 นาที · ฮาร์ดแวร์: คอมพิวเตอร์

เป้าหมาย ทำงานผ่าน Pull Request แบบทีมจริง และตั้งกฎให้ main เปลี่ยนได้ผ่าน PR เท่านั้น

Pull Request (PR) คือคำขอให้รวม branch หนึ่งเข้า main บน GitHub มีหน้าแสดง diff ให้คนอื่นอ่านและ comment ได้ และเป็นจุดที่ CI จะตรวจโค้ดให้อัตโนมัติก่อนรวม แม้ทำงานคนเดียว การผ่าน PR ก็ช่วยให้มีบันทึกว่าแต่ละการเปลี่ยนแปลงทำไปเพื่ออะไร

Hands-on: PR แรก

  1. สร้าง branch ใหม่ แล้วสร้างไฟล์ README.md ในโฟลเดอร์ repo (เปิดด้วย VS Code หรือ Notepad) เขียนสั้น ๆ ว่าโปรเจกต์นี้คืออะไร ต่อขาไหนบ้าง และ build อย่างไร
  2. commit แล้ว push branch ขึ้น GitHub จากนั้นสร้าง PR ด้วย gh pr create --fill (ใช้ข้อความ commit เป็นชื่อและคำอธิบาย PR)
  3. รัน gh pr view --web เพื่อเปิด PR บนเว็บ ดูแท็บ Files changed แล้วลอง comment บรรทัดใดบรรทัดหนึ่ง 1 จุด
  4. รวม PR ด้วย squash merge แล้วกลับมาที่ main ในเครื่องพร้อมดึงของใหม่ลงมา
terminal
git switch -c docs/readme
# เขียน README.md: รูป wiring, วิธี build, ขาที่ใช้
git add README.md
git commit -m "docs: add README with wiring and build steps"
git push -u origin docs/readme
gh pr create --fill
gh pr view --web
# ลอง comment โค้ดตัวเอง 1 จุดบนเว็บ แล้วกลับมารันต่อ
gh pr merge --squash --delete-branch
git switch main
git pull

ตั้งกฎให้ main

  1. เปิดหน้า repo บน GitHub ไปที่ Settings → Branches
  2. เพิ่มกฎสำหรับ branch main (ปุ่ม Add branch ruleset หรือ Add classic branch protection rule ชื่อปุ่มอาจต่างกันเล็กน้อยตามช่วงเวลาที่ GitHub ปรับหน้าเว็บ)
  3. เปิดตัวเลือก Require a pull request before merging แล้วบันทึก

ตอนนี้ยังไม่ต้องเปิด required status checks เพราะยังไม่มี CI จะกลับมาเปิดในบท 22 กฎนี้ใช้ได้ฟรีกับ repo แบบ public

เช็กความเข้าใจ

squash merge ดีอย่างไร?

รวม commit ย่อยใน PR เป็น commit เดียวบน main ประวัติอ่านง่าย 1 commit = 1 ฟีเจอร์ ย้อน (revert) ง่าย

ทำงานคนเดียว ทำไมยังต้องใช้ PR?

PR เป็นจุดที่ CI ตรวจโค้ดก่อนเข้า main และเก็บคำอธิบายว่าเปลี่ยนอะไรเพราะอะไรไว้ในที่เดียว ย้อนกลับไปดูหรือ revert ได้ง่าย

มุมงานจริง

ในทีม README ที่มีรูป wiring, badge CI สีเขียว และประวัติ commit ที่สะอาด ช่วยให้เพื่อนร่วมทีมหรือคนที่มารับงานต่อ setup และเข้าใจโปรเจกต์ได้ในไม่กี่นาที ไม่ต้องมาถามทีละเรื่อง
